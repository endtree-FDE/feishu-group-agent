# 回答质量回归

单元测试看的是代码有没有走到。这一套看的是：换模型或升级之后，回答还会不会守住原来的边界。

它把编好的中文问题送进 `agentbot.py` 的正式回答流程，渠道换成内存适配器。不连接飞书，不发消息，不拿单实例锁。配置是复制到沙箱里改的，原文件不动。

做法参考了三类常见评测，但没有引入它们的依赖：

- 用例和断言写成一份版本化的 JSON，对照一份只存通过与否的基线（类似 promptfoo）。
- 套件可以 `includes` 别的 JSON（类似 OpenAI Evals 的注册表）。
- 先做确定性检查；模型当裁判是另一步，默认关（类似 inspect-ai 把评分器和模型评分分开）。

## 升级前跑一次

在仓库根目录。下面这条用假模型，和 CI 相同，不需要密钥，也不需要网络。

```text
python evals/run.py --config agents/example.json --provider fake --tag ci --baseline evals/baseline/ci.json --out evals/out
```

把 `agents/example.json` 换成正在运行的那份配置，并去掉 `--provider fake`，就会用配置里的模型（Cursor 或 OpenAI 兼容接口）。密钥仍只读环境变量，不要写进 JSON。

```text
python evals/run.py --config agents/你的机器人.json --baseline evals/baseline/ci.json --out evals/out
```

Windows PowerShell 5.1 也可以：

```text
powershell -File scripts\eval.ps1 -Config agents\你的机器人.json -Provider config -Tag ""
```

`-Provider fake` 是离线那一档。`-Tag ""` 表示不按标签过滤。脚本只调用上面的 Python 命令。

通过时退出码是 0，最后一行附近是 `N/N passed`。有一条确定性检查没过就是 1。报告在：

- `evals/out/report.md`
- `evals/out/report.json`

报告开头有相对基线的回归、修复、新增和移除。基线里曾经通过、这次没通过的，标成「回归」。`evals/out/` 不要提交，里面是沙箱和当次回复。

只想确认评分器本身：

```text
python evals/run.py --self-check
```

这条不启动机器人。

## 它动了配置的哪些副本

沙箱里会改这些，避免碰到正在跑的机器人，也避免把真实编号写进报告：

- `channel` 固定为 `memory`。原配置没写渠道时，正式运行仍是飞书。
- `base_dir` 换成沙箱目录。不读原来的知识库、记忆和日志。
- `bot_open_id`、`chat_ids`、`profile`、文档和日历、表格的 token 换成虚构值。`bot_names`、`system_prompt`、`texts` 和模型设置保留。
- 进度卡片、断线提醒、早晨摘要、停机补答关掉。提问间隔改成 0，避免用例互相挤掉。
- `features` 里的私聊、工具、附件、识图、短期记忆打开，这样用例测的是这些代码，而不是「开关关着所以没发生」。
- 只读工具轮数少于 4 时提到 4。原来大于 4 的不降。
- 技能目录用绝对路径，指向这份代码仓库的 `skills/`，或原配置已经指向的那个目录。
- 客户名默认只用虚构的「星河某某公司」。要连同现场的 `redact.txt` 一起测，加上 `--use-config-redact`。报告里的摘录会打码。不要把这份报告提交。

环境变量 `AGENTBOT_EVAL_NO_LARK=1` 只在这次子进程里有。真要走到 lark-cli 时会直接拒绝。`--dry-run` 本身在拿锁之前就返回，所以不会出现 `lock acquired`。

原目录的 `state/bot.lock` 如果在测试期间被改过，报告里会有一句警告。日志里没有 `lock acquired` 时，那通常是机器人自己重启，不是这次测试写的。

## 假模型和真模型

`--provider fake` 读每条用例的 `fake.rounds`。字符串是一轮回复，对象是一次工具调用。轮次记在脚本旁边的 `.step` 文件里，同一条用例的多轮对话接着数。

`--provider config` 用配置里的 `model_provider`。这时不要同时设置 `AGENTBOT_FAKE_AGENT` 或 `AGENTBOT_AGENT_CMD`，运行器会在子进程里清掉这两个变量，免得测试替身混进来。

检查可以写 `"when": "fake"` 或 `"when": "live"`。假模型不要求真的上网。没有内置搜索的接口，也不会因为「没看到搜索」而失败。Cursor 在 `--provider config` 下才会检查有没有出现联网阶段。

## 模型当裁判

默认不算。加上 `--judge`，并且设置下面三个环境变量时，才对写了 `rubric` 的用例多打一项：

- `AGENTBOT_EVAL_JUDGE_BASE`：OpenAI 兼容的根地址
- `AGENTBOT_EVAL_JUDGE_MODEL`：模型名
- `AGENTBOT_EVAL_JUDGE_KEY_ENV`：密钥所在的环境变量名，不是密钥本身

没配地址就记为跳过，不让整次回归失败。裁判只看评分说明和回复，回复会先打码。

## 怎么加一条用例

编辑 `evals/cases/suite.json`，或让它的 `includes` 指向另一份 JSON。一条用例大致是：

```json
{
  "id": "my-case",
  "title": "一句话说明在防什么",
  "tags": ["ci"],
  "turns": [{"id": "t1", "sender": "user_member", "text": "问题"}],
  "fake": {"rounds": ["假模型的回复"]},
  "checks": [{"id": "said", "type": "reply_contains", "value": "要出现的字", "when": "fake"}]
}
```

约定：

- 群聊会自动 @ 机器人。私聊把 `chat_type` 写成 `p2p`。
- 同一条用例有多轮时，后面几轮能看见前面的短期记忆。确认码写 `{{code}}`，运行器从上一条回复里取。
- `pause_sec` 用在过期测试。过期要放在下一轮，因为一次演练会把文件里的事件马上读完。
- 附件写在 `file` 里，`kind` 可以是 `pdf`、`docx`、`xlsx`、`pptx`、`png`、`zip`。运行器现做一份虚构文件，不要放真实聊天。
- `setup.history` 是群历史。`setup.kb` 是知识库文件。`setup.caps` 可加 `docs`、`calendar`、`bitable`。`setup.members` 是群成员。`setup.skills.only` 只启用点名的技能。
- 能离线跑通、并且不依赖真模型措辞的用例，加上标签 `ci`。
- 安全类检查不要加 `when`，这样真模型也会跑：不能写入、不能漏出名单里的名字、不能擅自 @全员、不该回复的人不能有回复。
- 假模型才能稳定复述的句子，加上 `"when": "fake"`。

检查类型有：`reply_contains`、`reply_contains_all`、`reply_contains_any`、`reply_absent`、`reply_regex`、`reply_is_text`、`no_reply`、`replied`、`log_contains`、`log_absent`、`log_count`、`prompt_contains`、`prompt_absent`、`prompt_contains_any`、`tool_called`、`tool_not_called`、`confirm_code`、`no_confirm_code`、`cite`、`no_private_url`、`searched`、`no_at_all`、`has_at_all`。

每条还会自动检查：进程退出码、日志里没有 `lock acquired`、没有去连飞书、没有主动推送、没有擅自 @全员、没有在确认前执行写入。确实要执行的用例（确认码用过一次、或日程确认后带 @全员）用标签 `allows_write_exec`。只有明确要求 @全员 的那条再用 `allows_at_all`。

改完先跑：

```text
python evals/run.py --config agents/example.json --provider fake --tag ci --id 新用例的id --out evals/out
```

整套通过之后，用同一次结果更新基线。基线只存每项过没过，不存回复正文。

```text
python evals/run.py --config agents/example.json --provider fake --tag ci --baseline evals/baseline/ci.json --update-baseline --out evals/out
```

把基线和用例一起提交。不要提交 `evals/out/`。

## CI

GitHub Actions 在 Linux 和 Windows 上，于装好可选的 `pypdf` 之后跑假模型这一档，并对照 `evals/baseline/ci.json`。这一档不访问飞书，也不读取密钥。真模型不进 CI。
