## 攻击和结果

假模型和假的飞书命令，不连真飞书，也不使用真实群号或人名。

| 攻击 | 结果 | 说明 |
|---|---|---|
| 群消息或文档里夹带 `<<TOOL>>`，想绕过确认码和白名单直接写入 | 已修 | 历史、文档、日历、表格、附件里的工具标记会先换掉。当前这条用户问题里的标记仍然有效，否则正常的工具调用会坏。确认码和白名单仍在真正写入之前 |
| 用文档或网页内容套出知识库、别的群的记忆 | 部分 | 工具结果当不可信数据。对所有人开放私聊时，不在名单里的人不能调用飞书工具和技能。模型工作区仍是知识库目录，这一点没改 |
| 跨群串短期对话（伪造事件复用另一个群的话题编号） | 已修 | 群会话键改成「群编号 + 话题」。同一群同一话题仍复用常驻会话。长期记忆本来就按群分目录 |
| 把客户名、手机号、密钥放进搜索词或网页地址 | 已修 | 常驻模式拒绝这一次上网 |
| 八进制、十六进制、短写 IP、十进制整数、IPv6 本地地址、共享地址段 | 已修 | 一律当内网拒绝 |
| 域名解析失败 | 已修 | 以前失败仍放行，现在拒绝 |
| DNS 重绑定（两次解析结果不一致） | 部分 | 放行前查两次，不一致就拒绝。cursor-agent 拿到允许之后会自己再解析，那一次挡不住 |
| 公网地址再跳到内网 | 已修 | 自己看跳转目标，不跟着访问。探测失败时，这一跳本身已经检查过，仍允许这个地址 |
| 地址里带账号密码，或地址超过 1024 字 | 已修 | 拒绝 |
| 客户名中间插零宽字符 | 已修 | 去掉零宽后再匹配 |
| 较长名字拆开加空格 | 已修 | 6 个字及以上才做，避免短词误伤 |
| 全角数字的手机号、英文名大小写 | 已修 | 只把全角英文字母和数字折成半角。中文标点保持原样 |
| 拼音绕过 | 未修 | 没有词典。需要隐藏就在 `redact.txt` 写成「中文名\|拼音」 |
| 同形字（全角字母数字以外） | 未修 | 不整段做 NFKC，否则中文标点会被改写 |
| 超长消息把额度打光 | 已修 | `agent.max_input_chars` 默认 8000，`0` 表示不截断。原有的限流和队列还在 |
| 附件路径跳出下载目录 | 已修 | 真实路径必须在下载目录里 |
| 知识库压缩包用 `..`、绝对路径或盘符写到目录外 | 已修 | 可疑路径跳过并写进报告 |
| 日志、审计、权限标题里留下手机号或客户名 | 已修 | 这些字段先打码 |
| 私聊 `open_to_all` 被用来调工具 | 部分 | 只限制私聊：不在私聊名单、也不在写入白名单的人不能用工具和技能。已认群里的成员 @ 机器人仍可使用只读工具，写入仍要白名单和确认码。工作区仍是知识库 |
| 伪造邀请人：待认之后再发一次进群事件，把邀请人改成白名单 | 已修 | 来源是进群事件的待认群，后来的进群事件不能改成自动放行 |
| 非白名单发送 `/认群`，或在指令里夹零宽字符、尾巴 | 已修 | 只有写入白名单，且整句就是认群或忘群 |
| 进群事件重放，或把聊天消息伪装成进群 | 已修 | 带 `event_id` 的只处理一次。带着消息字段的不当成进群 |
| 没有 `event_id` 的进群事件重放 | 未修 | 和一次新的拉群分不开。若一律丢掉，合法的再次入群也会坏 |
| 移出后白名单成员再次拉进 | 不适用为漏洞 | 移出后再被 @ 会记成另一种待认。白名单成员再次拉进仍然重新认。这是原有规则，测试仍通过 |

## 这次加上的能力

默认行为保持不变，除非配置改了下面的数。

1. **长回答分片。** `agent.reply_chunk_chars` 默认 3500。不超过就不拆，幂等键仍是 `re_` 加消息编号。超过才拆成多条，每条开头是（1/N），幂等键是 `re_消息编号_序号`。`0` 表示不拆。模型输出仍先被 `max_chars` 截断，所以不把 `max_chars` 调大时，群里看到的还是一条。
2. **短期上下文按字数裁。** `memory.context_budget_chars` 默认 8000。只影响交给模型的历史，不删数据库里的记录。超预算时丢掉最旧的整段，最新一条留下。`0` 表示只按 `max_turns`。
3. **危险配置提示和一行指标。** `--check` 在非默认情况加 HINT：`p2p.open_to_all` 为 true 且私聊名单为空；`p2p.open_to_all` 与 `p2p.allow_group_members` 同时打开（仍由 `open_to_all` 决定谁能私聊）；自动认群生效且 `chats.admit` 为 `open`。示例配置和「私聊名单里有人、且没有打开群成员私聊」不会因此多出 HINT。每道交给模型的题多记一行 `metric`，里面没有问题原文。

## 路线

按价值，后面可以做、这次没做的：

- 按架构说明做记忆压缩（夜间把旧对话收成摘要）。会多调模型，先不要默认打开。
- 不引入插件市场。技能继续用仓库里的 `SKILL.md`。
- 对所有人开放私聊时，换一个没有知识库的工作区。这会改变能回答的范围，要单独决定。
- 拼音和同形字需要词典或人工名单，继续靠 `redact.txt` 的别名。
- 把 `metric` 送到外部监控。现在只进本机日志。

## 2026-10-18 再对照：值得借鉴的做法

线上还在升到 `873ce08`，这一节只记录对照结论。星数是当天 GitHub API 返回的公开数字，以后会变。链接都是当时能打开的仓库或文档。没有把真实账号、群号、客户名写进来。

本仓库仍然是：一份 JSON 一个机器人、飞书长连接、本地文件记忆、`SKILL.md` 技能、写操作走白名单和确认码。下面八项是成熟项目里和我们缺口最接近的做法。前三项各做一个草稿，互不叠在一起。技能名单和这一节在同一个改动里；省略说明和 `/状态` 是另外两个草稿。默认都不要求改已有的 `agents/*.json`：缺了键就保持原来的行为；省略说明只在本来就会裁掉旧对话时多一行。

| 借鉴什么 | 他们怎么做 | 我们现在 | 这次 |
|---|---|---|---|
| 技能选用名单 | 目录很大时按配置点名启用，而不是扫到就全塞进提示词 | `skills.enabled` 一开，文件夹里合法的技能全部进目录 | 做了。`skills.only` 不写或 `[]` 仍是全部 |
| 裁剪时留一句说明 | 上下文太长会压缩或先写摘要，避免模型以为更早的话没发生过 | 超预算时静默丢掉最旧的几条，数据库还在 | 做了。只加一句省略了几条，不另调模型 |
| 聊天里看状态 | 用一条命令或医生检查看开关，不必翻日志，也不必为此再问模型 | 只有本机日志里的一行 `metric` | 做了。`/状态` 不调用模型 |
| 记忆继续用本地小文件 | 长期事实、每日笔记、按人偏好分开，并且每块有字数上限 | 已有群档案、`facts.jsonl` 和「记一下」；个人记忆默认关 | 不改。不上托管记忆，也不让模型直接改档案 |
| 定时任务只做本机维护 | 有的框架用 cron 让机器人到点自己发言 | 已有知识库同步和看门狗；进群不打招呼 | 不改。不做出站定时消息 |
| 多模型用配置切换 | 一家不行就换另一家，密钥放在环境里 | 已有 `cursor` 和 `openai_compat` | 不改。不加重试时自动换一家（会多花额度） |
| 可观测性不记原文 | 面板或事件流看耗时和工具名，不把问题正文送出去 | `metric` 只记类型、长度、耗时、是否成功 | 不另做轨迹文件。`/状态` 也不打印路径和编号 |
| 技能是说明书，不是程序 | 官方技能按需加载领域说明；也有人让智能体自己写技能或跑脚本 | 技能只读 `SKILL.md`，写飞书仍要确认码 | 不改。不加插件市场，不执行技能附带的脚本 |

1. **技能按名单启用。** [OpenClaw](https://github.com/openclaw/openclaw)（约 39.2 万星）把技能放在多层目录里，再用配置决定哪些进会话（[技能说明](https://docs.openclaw.ai/skills)）。[飞书官方 OpenClaw 插件](https://github.com/larksuite/openclaw-lark)（约 2400 星）还能按群绑定技能和人设。[lark-cli](https://github.com/larksuite/cli)（约 1.8 万星）自己带二十多个 `SKILL.md`，用到再读（[技能目录](https://github.com/larksuite/cli/tree/main/skills)）。[Claude 的技能仓库](https://github.com/anthropics/skills)（约 18.2 万星）和 [agentskills.io](https://agentskills.io/specification) 也是先给目录、再读正文。我们已有目录和预放。缺的是「这个机器人只用其中几个」。`skills.only` 填名字列表后，目录、触发词预放和 `skill_read` 都只认这些名字；不写、`[]` 或 `false` 仍是全部。不照搬 ClawHub，也不让模型自己改技能。
2. **上下文裁短时说一声，但不要为了压缩再调一次模型。** [AstrBot](https://github.com/AstrBotDevs/AstrBot)（约 4.2 万星）有自动上下文压缩。[OpenClaw 的记忆结构](https://docs.openclaw.ai/concepts/memory-architecture) 在压缩前把要点写进文件。[CowAgent](https://github.com/zhayujie/CowAgent)（约 4.7 万星）在裁掉上下文时顺手存摘要。我们超预算时已经丢掉最旧的整条，短对话不裁。这次只在真的丢掉时加一句「省略了几条，本地还在」。`memory.trim_note` 不写或为 `true` 才加；写成 `false` 恢复原来的静默丢掉。不接夜间整理，避免每群再花一次模型。
3. **用一条命令看开关。** [NoneBot2](https://github.com/nonebot/nonebot2)（约 7800 星）把权限做成显式规则（[权限文档](https://nonebot.dev/docs/appendices/permission)）。[LangBot](https://github.com/langbot-app/LangBot)（约 1.8 万星）有访问控制、限流和监控。[Letta](https://github.com/letta-ai/letta)（约 2.5 万星）用 `/doctor` 看智能体状态。我们没有网页后台。`/状态`、`/status` 或单独一个「状态」直接回复：模型接口、短期记忆条数、长期记忆和技能开关、写入仍要确认码。不打印路径、profile、群号或密钥。`commands.status` 不写就是开；写成 `false` 时这几个字仍交给模型。「状态怎么样」这种句子不会被截走。
4. **记忆保持本地、可删、有上限。** [Letta 的 memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks) 把核心记忆分成有字数上限的块。[mem0](https://github.com/mem0ai/mem0)（约 6.7 万星，[论文](https://arxiv.org/abs/2504.19413)）从对话里抽取事实再检索。[OpenClaw 的记忆](https://docs.openclaw.ai/concepts/memory) 用 `MEMORY.md` 和按日的 Markdown。我们已有群档案预算、「记一下」和真删。不接入托管服务，也不让模型不经确认改档案。关键词检索事实留到以后，默认关着的长期记忆不必为它改提示词。
5. **定时任务不改成主动发言。** OpenClaw 有 cron 和 standing intents，Letta 也能给智能体加日程。[Dify](https://github.com/langgenius/dify)（约 15.9 万星）用会话变量和工作流保存中间结果（[会话变量说明](https://dify.ai/blog/dify-conversation-variables-building-a-simplified-openai-memory)）。我们的计划任务只做知识库同步和看门狗。机器人仍然不在进群时打招呼，也不做「到点往群里发一条」。
6. **换模型只通过配置。** AstrBot、LangBot、Dify 都接多家模型。我们缺省仍是 Cursor；`model_provider=openai_compat` 时密钥只在环境变量里。不增加「失败了自动再打另一家」，避免一次提问扣两次额度。
7. **日志继续不放问题原文。** [OpenHands](https://github.com/OpenHands/OpenHands)（约 9.1 万星）把动作记成事件，方便回放，执行放在沙箱里。把整段提示词写成轨迹文件会留下问题和工具结果，这次不做。已有的 `metric` 行保持只有长度和耗时。
8. **安全边界不放宽。** lark-cli 强调注入防护和终端输出打码；OpenClaw 还能安装社区技能。我们的技能仍然只是步骤说明，不能跑脚本，也不能绕过确认码。内网地址、裸写的假 IP、别的机器人的进程，都不因为这次对照而放行。

这次没有做的，也明确不进默认配置：插件市场、网页控制台、模型夜间重写档案、出站定时消息、失败后自动换模型、带原文的轨迹日志。

公开后这条分支的 Windows CI 还撞上两处竞态，都改成确定性的，不再靠重跑：

- 常驻进程和回退进程同时追加同一份跟踪时，Windows 会把 JSON 行写碎。锁文件在删除窗口里又会得到 `PermissionError`。现在每个事件单独落盘。测试是两个进程同时写，并检查每个文件都是一整行 JSON。
- 单实例锁先创建再写入时，另一个进程会读到空文件。测试只等文件出现就会读到空内容。现在先写成临时文件再改名，别人要么看到完整内容，要么看到文件还不存在。测试会等到锁里同时有进程号、`created=` 和 `base=` 再启动第二个进程。
