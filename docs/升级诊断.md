# 升级说明：诊断命令和结构化日志

不改配置也能跑。没有新的必填项。

## 诊断

```
python agentbot.py agents\<名字>.json --doctor
```

只读。不启动 `event consume`，不发消息，不写 `state\heartbeat`，不结束任何进程。

会看这些事：

- 配置里有没有 `app_secret`、`api_key`、`password`。有就失败，并且不把值打出来。
- `lark-cli --version`、`config show`、`auth status --json`（不带 `--as`）、`auth scopes`。`lark-cli` 1.0.98 不接受 `auth status --as bot` 和 `auth check --as bot`，带上会退出码 2。参数不被这一版接受时是警告，不是失败。
- 已经启用的能力所需要的 scope。`auth scopes` 列出了应用权限时，缺了就失败。列不出来是警告，到开放平台核对。没开的工具不因此要求权限。
- 需要哪些事件。只报名字，请到开放平台核对订阅。`event list` 列的是命令行认识的全部事件，不是这个应用的订阅，诊断不拿它判断成败。
- `open.feishu.cn` 能不能解析、443 通不通。解析到 `198.18/15` 且 `NO_PROXY` 没带飞书域名时给警告（假 IP 代理）。
- 可选包 `pypdf`、`openpyxl`、`pillow` 在不在。没有只是警告。
- 同一个目录是不是已经有两个正在服务的 `agentbot.py`，或者同一个 profile 的同一个事件有两个 `event consume`。`--doctor` 自己不算。

没有 FAIL 时退出码是 0，只有警告也是 0。有 FAIL 时退出码是 1。

## 日志

每答一题，除了原来的 `logs\bot.log`，还会追加 `logs\events.jsonl`。一行是一个 JSON，里面有消息编号、工具名、是否成功、飞书错误码和耗时。不写问题原文。手机号、邮箱、密钥样式的字符串会打码。

`events.jsonl` 超过约 2MB 会改名为 `.1`，最多留 5 份。

`logs\stdout.log`、`logs\stderr.log`、`logs\watchdog.log` 在启动脚本和看门狗里同样按大小改名。文件正被占用、改名失败时跳过，不结束进程。机器人自己的心跳里会再试一次截断。

不要把 `app_secret` 写进配置。

三个机器人升到这一版之后，用 `scripts\verify_windows.ps1` 做一次只读检查。它不发消息。步骤在 [部署后验证.md](部署后验证.md)，逐个升级和回退在 [升级三个机器人.md](升级三个机器人.md)。
