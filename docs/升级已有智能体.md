# 升级已有的飞书机器人

如果你已经有一个能在群里回话的机器人（下面用「小景」作例子），这篇是把它换成这套模板。

一次只做下面的一件事。做完在前面打勾，再看下一件。卡住了就停在那一件，把屏幕上的字原样留给帮你的人。不要一次做两件。

全程不要把 App Secret 写进文件、聊天或截图。旧的小景只停不删。出问题按文末「退回旧的」做。

下面所有命令，都在放着 `agentbot.py` 的那个文件夹里打开 PowerShell 再运行。

## 先确认（只看，先不改）

在你自己的电脑上打开 PowerShell。看完一条，把结果写在纸上，再看下一条。

1. 是不是 Windows 10 或 11。运行 `winver`。不是 Windows 就停。启动和看门狗脚本是 Windows 的，别的系统先别继续。
2. 有没有 Python。运行 `python --version`。把版本写下来。没有就先安装 Python 3.12，安装时勾选加入 PATH，然后关掉这个窗口，新开一个再查。
3. 有没有 git。运行 `git --version`。没有就去 git-scm.com 安装，选项保持默认。
4. 有没有 lark-cli。运行 `lark-cli --version`。再看这两个文件在不在：`%APPDATA%\npm\node_modules\@larksuite\cli\bin\lark-cli.exe`，或者 `%APPDATA%\npm\lark-cli.cmd`。程序先找前面那个 exe，没有才用后面的 cmd。两个都没有就先安装：`npm install -g @larksuite/cli`。
5. 这个应用配好了没有。运行 `lark-cli config show`。只看有没有你的机器人、profile 叫什么名字。不要把整屏截图发出去。不要抄 Secret。
6. 有没有 cursor-agent。打开文件夹 `%LOCALAPPDATA%\cursor-agent\versions`。里面要有子文件夹，而且至少一个子文件夹里同时有 `node.exe` 和 `index.js`。只有一半的文件夹不算，程序会跳过它。
7. 登录的是不是你自己的 Cursor 账号。运行 `cursor-agent login`，用你自己的账号登一次。额度算在这个账号上。配置里不写账号。
8. 飞书开放平台里，这个应用的「权限管理」已经开通了哪些。截「已开通」那一页即可，不要截凭证页。最少要有：`im:message.group_at_msg:readonly`、`im:message:send_as_bot`。要私聊再加 `im:message.p2p_msg:readonly`。群历史、文档、日历、表格、进度卡片可以以后再开。没开时它会说「这项权限未开」，不会崩。
9. 同一个后台里，「事件与回调」有没有 `im.message.receive_v1`，并且订阅方式是长连接。没有就先补上，并发布一个版本。
10. 旧机器人现在是怎么自己跑起来的。打开任务计划程序（运行 `taskschd.msc`）。再按 Win+R，输入 `shell:startup`，看启动文件夹。再看注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。再看有没有一直开着的黑窗口。把方式和旧文件夹路径写下来。
11. 旧机器人用的资料在哪个文件夹。把路径写下来。
12. 你的 GitHub 用户名是什么。写在纸上。以后如果要请别人把仓库分享给你，用的是这个名字。没有账号可以先空着，不影响在这台电脑上跑。

## 1. 先备份

不要删旧文件夹。

在同一个磁盘上复制一整份。名字加上「备份」和今天的日期，例如 `小景-备份`。

不要在备份里改东西。

## 2. 抄下旧设置

打开旧配置，抄到记事本。只抄这些：

- 机器人在群里的名字
- 第 5 条看到的 profile 名字
- 哪些群在用
- 你希望它怎么说话（去掉客户真名）

编号先别抄旧的。换过应用的话，人的编号会变，后面用小景这个应用重新查。

不要抄 App Secret。旧文件里如果有，删掉那一行。密钥只留在你电脑的 lark-cli 里。

## 3. 放新程序

不要覆盖旧文件夹。

新建一个文件夹，例如 `xiaojing-agent`。从本模板复制这些进去：

- `agentbot.py`、`tools.py`、`guard.py`、`kb_sync.py`、`memory.py`、`make_bundle.py`
- `scripts` 整个文件夹
- `tests` 整个文件夹
- `agents` 整个文件夹
- `redact.example.txt`
- `docs` 整个文件夹
- `kb` 文件夹

不要复制旧的 `state`、`logs`、`bot.pid`。

## 4. 放资料

把第 11 条写下来的旧资料（md 或 txt）复制进新文件夹的 `kb`。

不要用空文件夹盖掉原来的资料。原来的留在备份里。

## 5. 复制配置

在新文件夹里运行：

```text
copy agents\example.json agents\xiaojing.json
```

模板里的文件名是 `agents\example.json`。不要去找别的示例文件。

## 6. 打开配置

```text
notepad agents\xiaojing.json
```

## 7. 改名字

把 `"name"` 改成 `"xiaojing"`。

把 `"bot_names"` 改成 `["小景"]`。

保存。先别关记事本。

## 旧配置项改名对照

从旧机器人抄过来时，下面这些键已经改名。程序仍能读左边的旧名字，照常干活。`python agentbot.py agents\xiaojing.json --check` 会打出 `HINT`，提醒你改成右边。`HINT` 不算失败，`OK` 和 `FAIL` 的意思不变。两边都写了时，用新名字，旧的忽略，`HINT` 仍会叫你删掉旧的。

| 旧名字 | 现在写 |
|---|---|
| `tools.doc_search` | `tools.docs_search` |
| `tools.doc_read` | `tools.docs_read` |
| `tools.doc_create` | `tools.docs_create` |
| `tools.doc_append` | `tools.docs_append` |
| `write.resources.doc_folder_token` | `write.resources.folder_token` |
| `write.resources.doc_append_tokens` | `write.resources.docs_append_tokens` |

改完再跑一次 `--check`。没有 `HINT` 就说明这些旧名字已经不在了。然后继续第 8 步。

## 8. 把 base_dir 设成这个代码文件夹

这一项必须是放着 `agentbot.py` 的那个文件夹自己，不能是别的文件夹。

在这个文件夹的 PowerShell 里运行：

```text
(Get-Location).Path
```

把打出来的路径抄进 `"base_dir"`，并把反斜杠 `\` 全部换成正斜杠 `/`。

看门狗只读代码文件夹里的 `state\heartbeat`。程序把心跳写在 `base_dir` 下面的 `state`。两个地方不一致，看门狗会以为它死了，每 5 分钟重启一次。

保存。

## 9. 填 profile

把第 5 条看到的 profile 名字填进 `"profile"`。

还没有 profile 就先空着，做完下一件再回来填。

## 10. 没有 profile 时，由你本人输入密钥

已经有 profile 就跳过这一件。

由你本人运行（把应用 ID 换成你的，不要把 Secret 写在这一行里）：

```text
lark-cli config init --app-id 你的应用ID --app-secret-stdin --brand feishu
```

它停下来等你。粘贴 App Secret，按回车。屏幕上可能不显示，这是正常的。

然后再运行 `lark-cli config show`，把 profile 名字填进配置的 `"profile"`。保存。

## 11. 改它说的话

`"system_prompt"` 写成小景的人设。不要写客户真名。

如果旧人设里让模型自己在回复里写 `<at user_id="all"></at>`，把那一句换成下面这一句（其余人设不用动）：

```text
不要自己写 <at user_id="all"></at> 或其它 at 标签。只有对方原话明确要求 @全员 或通知所有人，并且这次是已经确认的日程操作时，才由程序在回复开头 @全员；不要邀请任何人。
```

假 IP 代理（Clash fake-ip）不用改配置也能打开公网网页：默认 `tools.web.allow_fake_ip_ranges` 是 `["198.18.0.0/15"]`。只有域名解析到这个段才放行，网址里直接写 `198.18.x` 仍然拒绝。局域网地址写进这个列表也不会放行。

`"texts"` 里的 `busy`、`empty`、`fail` 留下。把 `help` 改成一句话，说明小景能做什么。有人问「你能做什么」时，它直接回这句，不找模型。

保存。

## 12. 检查配置没写坏

```text
python -c "import json;json.load(open('agents/xiaojing.json',encoding='utf-8-sig'));print('ok')"
```

看到 `ok` 再继续。报错就回到记事本，看是不是少了引号或逗号。改完再运行这一行。

## 13. 先不要开记忆和进度

在 `xiaojing.json` 里确认这两项，然后保存：

- `"memory"` 里的 `"enabled"` 是 `false`
- `"progress"` 里的 `"enabled"` 是 `false`

`"features"` 里的 `"p2p"` 保持 `true`，这样等一下可以私聊验收。

`"write"` 里的 `"enabled"` 先保持 `false`。先不让它建文档、建日程、改表格。

## 14. 查群编号

机器人先拉进那个群。然后（profile 换成你的）：

```text
lark-cli im +chat-list --as bot --profile 你的profile --page-all --format json
```

找到群的名字，把旁边的编号填进 `"chat_ids"`。只有一项就写成一个数组。保存。

现有机器人做到这里即可。`chat_ids` 里写了群，就只回答这些群，和以前一样。

## 14 附（可选）：拉进群就认，不用每次改群号

只有当你希望以后把机器人拉进新群、不用再改配置时，才做下面这些。已经按第 14 步填好 `chat_ids` 的，不要改，跳到第 15 步。

1. 把 `"chat_ids"` 改成 `[]`。
2. `"chats"` 里的 `"auto_join"` 改成 `true`。`"admit"` 保持 `"confirm"`。这是安全默认：陌生人把它拉进群，也不会调用模型。
3. 保存。不要在群里发「大家好」。程序也不会自己打招呼。
4. 飞书开放平台补两个权限，然后重新发布版本：`im:chat:read`（启动时列出已经在的群）、`im:chat.members:bot_access`（知道自己被拉进或移出）。在「事件与回调」里，除了原来的 `im.message.receive_v1`，再订阅 `im.chat.member.bot.added_v1` 和 `im.chat.member.bot.deleted_v1`，方式仍是长连接。没订上也不会崩：已经在的群靠启动时的列表记账，新拉进去的群靠有人 @ 它来记账。
5. 重启之后，新群里有人 @ 它，它先不回答。`write.allowed_users` 里的人在那个群 @ 它，只发送：

```text
/认群
```

它回复一句「已认这个群」之后，这个群里别人 @ 它才会回答。每个群的记忆单独放在 `memory/groups/群编号/`。不想再回答时，同一个人 @ 它发送 `/忘群`。记忆文件还留着，只是不再回答。再发 `/认群` 可以恢复。

`"admit"` 还可以写成 `whitelist` 或 `open`，含义见 [agents/CONFIG.md](../agents/CONFIG.md)。`whitelist` 只自动接受白名单里的人拉进去的群。`open` 是所在的群被 @ 就回答，谁都能把它拉进去消耗额度，一般不要用。三种都只在被 @ 时说话。

## 15. 查机器人自己的编号

把上一步的群编号贴到 `--chat-id` 后面：

```text
lark-cli im +chat-members-list --chat-id 群编号 --as bot --profile 你的profile --page-all --format json
```

`bots` 里小景的 `member_id` 填进 `"bot_open_id"`。必须用这个应用查出来的编号。保存。

## 16. 写下你自己的编号

同一份输出里，`users` 中你的 `member_id` 填进 `"write"` → `"allowed_users"`。左边是编号，右边是你的称呼。

私聊默认只放行这份名单里的人。你不写进去，等一下私聊它不会理你。

保存。再运行第 12 步那一行，看到 `ok`。

## 25. 停旧的

按第 10 条写下来的方式，把旧小景停掉。关窗口，或在任务计划程序里结束它。

只停，不删文件。

## 26. 关掉旧的自启

任务计划程序里，会启动旧文件夹的任务：右键禁用。不要删除。

启动文件夹里的快捷方式，挪到桌面一个「旧小景备份」文件夹。不要直接删。

不关的话，下次登录两个会一起抢消息，群里会收到两次回复。

## 27. 如果旧的还有 pid 文件

旧文件夹里如果有 `bot.pid`，把它的完整路径写进正式配置的 `"conflict_pidfiles"`，斜杠用 `/`。没有就保持 `[]`。

保存。再跑一次第 12 步，看到 `ok`。

旧的还活着时，新的会拒绝启动。程序自己启动时会查这份列表。`scripts\start.ps1` 启动前也会查：pid 还在就打出 `REFUSED` 并且不启动，也不会去结束那个旧进程。看门狗和 `switch-from-old.ps1` 都是通过 `start.ps1` 启动的，所以同样会拒绝。

启动前，`start.ps1` 还会结束同一个 lark-cli profile 里残留的 `event consume` 和 `event _bus`。只认配置里这个 profile 的 `--profile`，别的 profile 不动。本目录已经在跑时，不会去结束它自己的那两个进程。旧程序还活着时先拒绝，所以不会误伤它。

旧的如果是后来才起来的，`conflict_pidfiles` 挡不住，所以第 26 步不能省。

`-Name` 决定任务名字。下面用的 `Xiaojing-Start` 和 `Xiaojing-Watchdog` 就是这么来的。你如果改了 `-Name`，后面两处名字一起改。

```text

```

出现 `ready event_key` 或 `feishu-websocket: connected`，就是连上了。

90 秒还没有成功那两个字，去做文末「退回旧的」。不要在群里发消息试。

## 31. 看一眼看门狗

```text
Start-ScheduledTask Xiaojing-Watchdog
```

再打开 `logs\watchdog.log`。不应出现新的 `restart` 行。

如果每隔大约 5 分钟就有一行 `restart`，先回到第 8 步：`base_dir` 是不是这个代码文件夹。看门狗每 5 分钟跑一次，心跳文件不在它找的地方，它就会一直重启。

## 32. 私聊验收，不要在群里发

由你本人在飞书里私聊小景。一条一条发。

需要它思考的问题，两条之间至少隔 20 秒。这个秒数是配置里 `rate_limit.min_gap_per_user`，示例就是 20。隔得更短，这条会被悄悄丢掉，不会回复「太快了」，日志里也像没发生。问「你能做什么」、发「/记忆」或「记一下」不受这 20 秒限制，但仍然一次只发一条。

1. 发 `你能做什么`。应回你写的 help 那句话。
2. 等够 20 秒。发一个资料里有答案的问题。应回答，并说出资料的名字。
3. 发 `/记忆`。应说私聊里没有群档案。这是正常的，群记忆只在群里用。
4. 发 `记一下：测试`。应说私聊里的事不会记进群记忆。这是正常的。正式配置里记忆还关着时，也可能先说还没开启长期记忆。两种都说明它没有把私聊写进群里。
5. 看日志：

```text
Get-Content logs\bot.log -Tail 20
```

每条都应有一行 `Q`，并且回复是 `ok=True`。没有 `Q`，回到第 9 条：事件、发布、可用范围，以及旧的是不是还在抢。

先不要在群里发测试消息。

## 退回旧的

新的有问题，按顺序做这三件。不要删新文件夹。

1. 停新的：

```text
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\stop.ps1
```

2. 关掉新的自启：

```text
Disable-ScheduledTask -TaskName Xiaojing-Start
Disable-ScheduledTask -TaskName Xiaojing-Watchdog
```

3. 恢复旧的：在任务计划程序里，把第 26 步禁用的旧任务启用；或者把快捷方式放回启动文件夹。再按原来的方式启动旧小景。

群里就回到升级前。新文件夹、记忆、日志都还在。

修好之后要再上线：运行 `Enable-ScheduledTask -TaskName Xiaojing-Start`，同样启用 `Xiaojing-Watchdog`，然后 `Start-ScheduledTask Xiaojing-Start`。

也可以用脚本从旧目录切到新目录（把路径换成你的备份或旧文件夹）：

```text
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\switch-from-old.ps1 -Old "D:\小景-备份" -Config "agents\xiaojing.json"
```

它会停旧的、启动新的。大约 90 秒内日志没有 `ready` 或 `connected`，会自己停新的并启动旧的。旧文件夹的根目录里要有 `stop.ps1` 和 `start.ps1`，脚本找的是这两个文件，不是 `scripts` 子文件夹里的。没有就不要用这一行，按上面三步手动退回。这个脚本不能代替第 1 步的整份备份。`-Old` 必须写，没有默认路径。

## 常见卡点

- 中文变成问号：不要用 PowerShell 管道把中文交给 python。演练用 `--dry-run dry.jsonl` 这种文件。
- 连飞书时报 EOF：`scripts\start.ps1` 已经设置了不走代理的域名（`open.feishu.cn`、`.feishu.cn`、`.larksuite.com`）。你如果开了代理软件，把这几个域名设成直连。
- 日志里出现 `Cannot use this model`：多半是 Cursor 这边暂时不能用配置里的模型。程序会自己去掉模型名字再试一次。一直失败就回到第 7 条，确认 `cursor-agent login` 是你自己的账号，并且这个账号能用 `grok-4.7-high-fast`。不能用就改 `agent.model`。
- 电脑睡眠会掉线。看门狗会在本机把它拉起来，不会往群里发消息。长期开着就关掉睡眠。
- 日志里一条 `Q` 都没有：查第 9 条的事件是不是长连接、应用有没有发布、可用范围有没有包括你，以及旧小景是不是还在跑。
- 看门狗大约每 5 分钟重启一次：`base_dir` 不是这个代码文件夹。回到第 8 步。

## 后来加的开关：截断后的事实召回

旧的 json 不用改。长期记忆本来就是关的，关着时提示词和以前一样。已经把 `memory.enabled` 设成 `true` 的，档案超了字数预算、并且这一题命中了被截掉的条目时，提示词会在问题前多几行。不想要这几行，就在 `memory` 里加 `"recall": false`。写入仍要白名单和确认码，不会因为多了这几行就自动改档案。

## 后来加的开关：本机日志

旧的 json 不用改。每道交给模型的题会在 `logs/journal.jsonl` 追加一行字数和工具名，不写问题原文。不想要这个文件，就加上 `"observability": {"journal": false}`。`logs/bot.log` 里原来的 `metric` 行还在。

## 后来加的开关：知识库目录

旧的 json 不用改。没写 `kb_index` 时，知识库为空的回答和以前一样。文件夹里有 `.md` 或 `.txt` 之后，提示词会多一份文件名和标题，正文仍要模型用 `kb_read` 来读。不想要这份目录，就加上 `"kb_index": {"enabled": false}`。不想让它读文件，就在 `tools` 里写 `"kb_read": {"enabled": false}`。写入、确认码和「不主动发消息」都不变。

## 后来加的开关：模型预设

旧的 json 不用改。没写 `model_provider`，或仍是 `cursor`，回答还是走本机 Cursor。把 `model_provider` 写成 `deepseek`、`dashscope`、`zhipu` 或 `pangu` 时，只补上还空着的 `base_url`、`model` 和 `api_key_env`。已经写了的这三项保持原样。密钥仍只放在环境变量里，不要写进 JSON。
