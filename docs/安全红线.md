# 安全红线

这些规则不要放宽。配置可以少开能力，不能绕过确认。

## 写之前要过三道锁

新建文档、在文档末尾追加、建日程（可以一次提多个）、修改日程、删除日程、往多维表格加一条记录，都是写操作。三道锁同时满足才执行：

1. **人**：发起人在 `write.allowed_users` 里。
2. **东西**：只能写配置里点名的文件夹、文档、日历、表。别的文档、别的表，直接拒绝。
3. **动作**：程序只允许上面那几类。没有删消息、没有删文档、没有删表格记录、没有覆盖全文、没有改权限、没有邀请别人。改日程和删日程也在这道锁里，命令固定不通知参会人。

缺任何一道，都不执行。

## 确认码

提议写的时候，机器人发一个 6 位数，并说明要做什么。

发起人必须在 5 分钟内（可在 `write.confirm_ttl_sec` 里改时间），**在原来的会话里 @ 机器人**，回复：

```text
确认 123456
```

取消则回复：

```text
取消 123456
```

规则：

- 只有发起人本人可以确认。别人拿到数字也不行。
- 码只用一次。用过、取消过、过期了，都失效。
- 确认码存在本机 `state/state.db`。进程重启后，没过期的码还在；过期就作废。
- 确认之前，飞书上的文档和表不会被改。

## 明确不做的事

- 不删除消息、文档或表格记录。日程可以改、可以删，但必须是白名单发起人用确认码点头，而且不会顺带通知或增删参会人。
- 不覆盖已有文档的正文（只允许在白名单文档的**末尾追加**）。
- 不修改文件或群的权限，不把新人拉进群，不邀请别人进日程。
- 不替团队派任务、不代表团队对外承诺。不 @ 别人。唯一例外：对方原话明确要求 @全员 或通知所有人，并且这次是已经确认的日程操作，回复开头可以带一次 @全员。模型不能自己写 `<at user_id="all">`，也不能把人邀请进日程。
- 打开网页只放行公网。本机、局域网、链路本地和共享地址拒绝。假 IP 代理把域名解析到 `198.18.0.0/15` 时，只放行「用域名访问且解析落在 `tools.web.allow_fake_ip_ranges` 里」的那一种；裸 IP 和跳进内网仍然拒绝。
- **不主动发消息。** 只回复群里 @ 它的消息，以及你允许的私聊。若配置打开了话题续问，它已经答过的话题里，发起人或白名单成员可以不 @ 接着问；它仍然不会自己开口。拉进群、列出已在的群、被移出群，都只记账，不在群里打招呼。
- **群要先被允许。** 默认只回答 `chat_ids` 里的群。打开自动认群后，默认还要写入白名单里的人在那个群 @ 它并发送「/认群」，它才回答、才调用模型。陌生人把它拉进别的群，@ 它也不会消耗额度。待认的群，后来的进群事件不能改邀请人并自动放行。带 `event_id` 的进群、出群事件只处理一次。
- **私聊名单。** `p2p.open_to_all` 为 true 且没有把这个人写进 `allow_open_ids` 或写入白名单时，这个人私聊只能聊天，不能调用飞书工具或技能。已认群里的成员 @ 机器人不受这条限制，只读工具照常可用，写入仍要白名单和确认码。模型的工作区仍然是知识库，所以不建议对所有人开放私聊。
- **不要为了测试，自己往正式群里发消息。** 上线验收请一位真人私聊一次、在群里 @ 一次。

## 客户名和隐私

每个机器人一份 `redact.txt`（从 `redact.example.txt` 复制）。一行一个要隐藏的客户名，也可以写成「中文名|拼音」。回答、进度卡片、记忆、知识库同步、日志和审计，都会把这些名字换成「某客户」。全角、零宽字符，以及在较长名字中间插空格，也会被换成「某客户」。没有写进名单的拼音不会自动识别。

另外一律打码，不用你列名单：

- 手机号
- 身份证号这一类 18 位证件号
- 邮箱
- 看起来像密钥的字符串（例如写了 secret、token、password 的那一行）
- 电脑上的路径

话题红线不是框架自带的。`policy.redlines` 默认是空的，不拦任何话题。你要是不希望它讨论某类事，在自己的配置里加规则。见 `agents/CONFIG.md`。

机器人之间不靠屏蔽词隔离。每个机器人只读自己的知识库，只写自己群的记忆。

## 密钥和账号

- 应用密钥（App Secret）不写进 json，不发到群里，不贴给帮你操作的人。由你本人在自己电脑上运行 `lark-cli config init --app-id 你的应用ID --app-secret-stdin`，在提示后粘贴。
- 模型用的是这台电脑上 `cursor-agent login` 登录的 Cursor 账号和额度。配置里只写模型名字（默认 `grok-4.7-high-fast`），不写账号。
- 填好真实群编号、文档编号的配置文件，不要放进公开仓库。

## 审计

读写都会在 `audit/` 里按月记一行：谁、什么时候、做了什么。记忆的增删在 `memory/_audit/` 里，删除只留编号，不留被删的内容。出了问题先看这两处和 `logs/bot.log`。
