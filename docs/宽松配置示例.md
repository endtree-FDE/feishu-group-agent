# 宽松配置示例

默认值是为了省额度。额度充足时，不必把只读轮数、附件数、PDF 页数、文档字数和各项读取上限都卡在默认上。下面这段是可选的。不抄进自己的 `agents/*.json`，行为与现在的默认完全一样。

仓库里的 `agents/example.json` 不采用这段，程序里的默认值也不改。确认码、写入白名单、谁可以记和删，都不在这里放宽。

把需要的键合并进自己的配置即可。这不是一份能直接启动的完整配置，名字和群号仍用你自己的。

| 想放宽的 | 键 | 不写时 | 这段示例 |
|---|---|---|---|
| 只读轮数 | `agent.max_tool_rounds` | 4 | 16 |
| 一次回答里的历史附件数 | `tools.message_attachment.max_per_answer` | 4 | 20 |
| PDF 抽文字的页数 | `tools.attachment.pdf_max_pages` | 20 | 80 |
| PDF 没有文字时，往前翻多少页找内嵌图片 | `tools.attachment.pdf_scan_pages` | 10 | 40 |
| 这些页里最多抽出几张图 | `tools.attachment.pdf_max_images` | 3 | 12 |
| 一份云文档读进提示词的字数 | `tools.docs_read.max_chars` | 20000 | 80000 |
| 工具结果送进模型的字数 | `agent.body_max_chars` | 20000 | 80000 |
| 附件正文的字数 | `tools.attachment.max_chars` | 跟 `body_max_chars`，默认 20000 | 80000 |
| 群历史交给模型的行数 | `tools.history.max_lines` | 150 | 600 |
| 搜索文档的字数 | `tools.docs_search.max_chars` | 4000 | 16000 |
| 读日历的字数 | `tools.calendar_read.max_chars` | 4000 | 16000 |
| 读多维表格的字数 | `tools.base_read.max_chars` | 5000 | 20000 |
| 一条短期记忆的字数 | `memory.max_turn_chars` | 2000 | 8000 |
| 多轮工具结果的总预算 | `agent.tool_context_budget_chars` | 120000 | 480000 |

文档和附件的正文还会再被 `body_max_chars` 截一次。只把 `docs_read.max_chars` 调大、不调 `body_max_chars`，多出来的字仍然进不了提示词。所以这段把三个字数一起调大。`pdf_max_images` 不写仍是 3；页数调大之后，扫描页最多也只抽出 3 张图，所以示例里一并调高。

`tool_context_budget_chars` 管的是多轮读完之后重新发给模型的总量。单份文档先被自己的 `max_chars` 截过，再受这个总预算约束。写成 `0` 表示不设总预算；这段仍给一个更大的有限数字。

回答本身仍按 `agent.max_chars`（默认 3500）截断。这段不改回答长度，也不改每条飞书消息的拆分长度。

```json
{
  "agent": {
    "max_tool_rounds": 16,
    "body_max_chars": 80000,
    "tool_context_budget_chars": 480000
  },
  "memory": {
    "max_turn_chars": 8000
  },
  "tools": {
    "history": {
      "max_lines": 600
    },
    "docs_search": {
      "max_chars": 16000
    },
    "docs_read": {
      "max_chars": 80000
    },
    "calendar_read": {
      "max_chars": 16000
    },
    "base_read": {
      "max_chars": 20000
    },
    "attachment": {
      "max_chars": 80000,
      "pdf_max_pages": 80,
      "pdf_scan_pages": 40,
      "pdf_max_images": 12
    },
    "message_attachment": {
      "max_per_answer": 20
    }
  }
}
```

写操作仍然先发确认码。不回复确认码，程序不会新建文档、改日程或删日程。

## English

Optional larger read limits for operators who have quota to spare. Defaults stay 4 tool rounds, 4 attachments per answer, 20 PDF text pages, 10 PDF image-scan pages, 3 embedded images, 20000 document characters, 150 history lines, 4000 search and calendar characters, 5000 Bitable characters, 2000 characters per short-term turn, and 120000 characters of tool context. Copy only the keys you want into your own config. `agents/example.json` is unchanged. This does not loosen confirmation codes or write allow-lists.
