# 运行可靠性：升级说明

这一页只讲进程、启停、日志和诊断。不改飞书消息怎么解析，也不改模型人设。

旧的 JSON 不改也能启动。下面每一项都是「没写就保持原来的行为」。想用上新行为，按这一节改配置，然后停掉再启动。

## 这一批：常驻进程卡死、心跳、set_config_option

### 你要改的配置

在 `agent` 里可以加两项。不写也行。

| 键 | 旧行为（不写） | 建议 |
|---|---|---|
| `max_runtime_sec` | 仍是 1800 秒。到点这一题停止。 | 长答案经常被截断时，改成 `0`。`0` 表示不设硬时限。 |
| `progress_heartbeat_sec` | 按 20 秒。 | 一般不用改。写成 `0` 关掉心跳日志。 |
| `stall_sec` | 仍是 300 秒没有任何新输出就当成卡住。 | 不要写成 0。写成 0 也会按 300 秒，避免把卡死检测关掉。 |

`max_runtime_sec` 大于 0 时，和以前一样到点就停。常驻模式这一题改走原来的一次性进程；一次性模式尽量把已经写出的部分发出去。

### 运行时会看到什么

- 日志里多了 `acp pulse` 或 `agent pulse`：这一题还在，后面是已经用了多久、多久没有新输出。
- 进度卡片开着、并且超过一个心跳周期完全没有新输出时，阶段会变成「已经 N 秒没有新输出」。模型还在往外吐字时，原来的「正在读」「正在查」不会被这句盖掉。
- 常驻进程自己退出（没人在问）时，日志是 `acp exited`，接着 `acp restart`。10 分钟内退出满 5 次，日志是 `acp restart paused after repeated exits`，下一题再试着拉起。
- `session/set_config_option` 现在带 `type: "id"`。这是现行 ACP 要求的字段。2026-10 的 cursor-agent 对缺这个字段的请求回 `Invalid params`，答题本身以前也能完成，但日志里会有这条协议错误。对不上可选值、或当前值已经一致时，仍然不发这个请求。带 `type` 仍被拒绝时，会再试一次不带 `type` 的旧写法。两次都失败只记 debug，这一题继续。模型仍然主要靠启动参数 `--model`。

### 怎么确认

1. `python agentbot.py agents\<名字>.json --check`。`mode` 为 `acp` 时仍要看到 `OK   acp`。
2. 问一题较慢的问题。`logs/bot.log` 里应出现 `acp pulse` 或 `agent pulse`，而不是刚到 1800 秒就被截断（只有你把 `max_runtime_sec` 改成 `0` 之后才没有总时长上限）。
3. 不需要改 `scripts\start.ps1` / `stop.ps1`。停进程的方式没变：仍然只停本目录、命令行对得上的那个进程。

### 退回

把 `max_runtime_sec` 改回 `1800`，删掉 `progress_heartbeat_sec` 也行（不写就是 20 秒心跳，不影响答案）。协议字段是程序里的，不用在配置里开关。
