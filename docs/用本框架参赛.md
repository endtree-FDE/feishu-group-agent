# 用本框架参赛

这份说明写的是：比赛如果要求用 openJiuwen / JiuwenSwarm 那一类 OpenAI 兼容模型，怎样把地址接到本仓库，同时留下飞书这边的门卫。本仓库不是 JiuwenSwarm 的内嵌副本，也不代替赛题自己的运行时。

写于 2026-10-18，对照的是当时能打开的公开文档。比赛地址以主办方当届页面为准。

## 本仓库守住什么

换模型不换这些规则：

- 只在被 @ 或被允许的私聊里回答，不主动往群里发消息，不邀请人。
- 写入飞书仍要白名单，并且由发起人本人回复 6 位确认码。
- 不代发 `@全员`。只有对方原话要求，并且是已经确认的日程操作，才由程序加上这个标记。
- 客户名和密钥样子的字符串按脱敏规则处理。
- 密钥、股票池、赛题数据、真实群号和客户名不放进这个仓库。

模型只负责写文字和提出工具调用。能不能写、写到哪里，由程序决定。

## 和 JiuwenSwarm 怎么对应

JiuwenSwarm 的模型配置（网页或 `.env`）常见这四项。他们的 `api_base` 不要自己加上 `/chat/completions`，程序会补。本仓库的 `chat_url` 也是这样：地址末尾没有这段时会补上。

| JiuwenSwarm | 本仓库 | 放什么 |
|---|---|---|
| `API_BASE` / `api_base` | `agent.base_url` | 主办方给的地址。不要在问号后面写密钥。 |
| `MODEL_NAME` / `model` / `model_name` | `agent.model` | 主办方给的模型名。 |
| `API_KEY` / `api_key` | 环境变量 | 值只放在环境变量里。JSON 里只写变量名 `agent.api_key_env`。 |
| `MODEL_PROVIDER` | `model_provider` | 见下一节。不要把 Jiuwen 的 `API_KEY` 抄进这一项。 |

公开文档里，JiuwenSwarm 写明能接的平台包括华为云 MaaS、OpenAI、DeepSeek、DashScope（通义）、SiliconFlow、OpenRouter，以及别的 OpenAI 兼容地址。字段说明见 [JiuwenSwarm 配置](https://github.com/openJiuwen-ai/jiuwenswarm/blob/develop/docs/en/Configuration.md) 和 [FAQ](https://github.com/openJiuwen-ai/jiuwenswarm/blob/develop/docs/en/FAQ.md)。

本仓库没有名叫 `jiuwen` 的预设。同一套 OpenAI 兼容接口就够。

## 选预设，还是原样填主办方的地址

预设只适合主办方没有另给地址、而你用的就是这家公开接口的时候：

| `model_provider` | 地址 | 默认模型名 | 环境变量名 |
|---|---|---|---|
| `deepseek` | `https://api.deepseek.com` | `deepseek-flash` | `DEEPSEEK_API_KEY` |
| `dashscope` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | `DASHSCOPE_API_KEY` |
| `zhipu` | `https://open.bigmodel.cn/api/paas/v4` | `glm-5.3` | `ZAI_API_KEY` |
| `pangu` | `https://api.modelarts-maas.com/openai/v1` | `openpangu-2.0-flash` | `MAAS_API_KEY` |

`pangu` 用的是华为云 MaaS 文档里的 OpenAI 兼容地址（西南-贵阳一这一档公开示例）。主办方如果给了别的区域或别的路径，不要猜，改用下面的写法。

主办方给了 `API_BASE` 时，用 `openai_compat`，三项都写上。这样不会被预设填成另一家的公开地址。

```json
"model_provider": "openai_compat",
"agent": {
  "base_url": "https://主办方给的地址",
  "model": "主办方给的模型名",
  "api_key_env": "CONTEST_API_KEY"
}
```

然后在运行这台程序的环境里设置 `CONTEST_API_KEY`，不要写进 JSON，不要提交。变量名可以自己起，只要和 `api_key_env` 一致。

已经写在 `agent` 里的 `base_url`、`model`、`api_key_env` 优先于预设。没写 `model_provider` 时仍是本机 Cursor，和旧配置一样。

干跑看结果、不写文件：

```text
python setup_agent.py --name contest --provider openai_compat --base-url https://example.com/v1 --model your-model --api-key-env CONTEST_API_KEY --dry-run
```

写好之后可以用 `python checks/check_config.py agents/contest.json` 看类型。这个文件在 `.gitignore` 里，不要强制加进 Git。

## 赛题和本仓库各管一截

2026 年 CCF BDCI 上和 openJiuwen 相关的公开入口包括财经报道、职场、量化和论文方向，以及 CareerSim 的说明仓库。链接记在 [roadmap.md](roadmap.md) 第 17 项。那些仓库里的股票池、简历、论文数据和密钥留在赛题仓库，不要复制进这里。

可以让两边指向同一个模型地址：JiuwenSwarm 用它跑赛题逻辑，本仓库用它在飞书里回答。不要为了比赛再自动接第二家模型。备用模型是路线图第 8 项，默认关着。

飞书侧的工具、确认码和脱敏不会因为模型换成盘古或 DeepSeek 就放开。

## English

This repository is the Feishu gate: allow-list, six-digit confirm, redaction, and the OpenAI-compatible model slot. It does not embed JiuwenSwarm.

Map `API_BASE` to `agent.base_url`, `MODEL_NAME` to `agent.model`, and put `API_KEY` only in the environment variable named by `agent.api_key_env`. Do not append `/chat/completions` yourself. If the contest gives its own base URL, set `model_provider` to `openai_compat` and fill all three fields. Presets (`deepseek`, `dashscope`, `zhipu`, `pangu`) are only for those vendors' public endpoints.

Do not commit contest datasets, stock lists, or API keys. Writes still need the allow-list and the initiator's confirm code. The bot does not send group messages on its own.
