# 从 0.4.0 升到 0.4.1

这一版不改配置也能接着跑。程序不读 `VERSION`。不要把 App Secret、群号、open_id 或客户名写进配置或聊天。

发布说明见 [v0.4.1](release-0.4.1.md)。

## 停和启

1. 用本目录的 `scripts\stop.ps1` 停掉这个机器人。它仍只看本目录和 profile，不会结束旁边另一个机器人。
2. 换成这一版代码。保留原来的 `agents\*.json`、`state`、`kb` 和 `redact.txt`。
3. 用原来的 `scripts\start.ps1` 再启动。

旧的 `state\bot.lock` 如果只有一行进程号，仍然认。新写的锁会先写完整内容，再让别的进程看见。不用手工删锁。

同一个飞书应用只能有一个接收进程。另一个目录用同一个应用再启动会被拒绝，不会结束已经在跑的那个。两个不同的应用可以各跑一个。

## 确认码

第一次用到确认码时，程序会在 `state\state.db` 里自己建 `used_writes` 表。不用手工建表，也不用删旧库。

- 还没使用、也没过期的码，重启后仍然有效。
- 用过或取消过的码先记入这张表，重启后也不能再执行。
- 新码如果和还有效的码相同，不会覆盖原来的那次操作。
- 确认必须是发起人本人，并且在原来的会话和话题里。主聊天的码不绑单条消息编号。别人、别的群、别的私聊、别的话题都不能确认。发错不会把码用掉。

确认、状态、帮助和记忆命令不再受单人提问间隔限制。每分钟仍有上限，不写 `rate_limit.max_commands_per_min` 时是 40。写成 `0` 表示不限这条。普通提问仍走原来的间隔。

## 私聊按群成员（可选）

不改配置时，私聊范围和 0.4.0 一样，不会去查群成员。

要让所服务群的当前成员也能私聊，才做下面这些：

1. 在飞书开放平台给这个应用加上 `im:chat.members:read`，并发布应用版本。
2. 确认 `features.p2p` 仍是 `true`。
3. 在 `p2p` 里加上 `"allow_group_members": true`。`member_cache_ttl_sec` 可以不写，默认 600 秒。
4. 改完 JSON 后重启进程。进群、退群最迟大约一个缓存周期才生效。

`open_to_all` 为 `true` 时，谁能私聊仍由它决定。查成员失败、超时、缺权限或名单不完整时，不在 `allow_open_ids` 和写入白名单里的人不会得到回复。

有一处比 0.4.0 宽，和这个开关无关：`allow_open_ids` 非空时，写入白名单里的人即使不在这份名单里也可以私聊。写入本身仍要白名单和 6 位确认码。
