# 分群知识库

机器人原来要等你问到某一份文件，才临时去读。这里多了一种可选能力：把一个群（或一次私聊）的资料先收成可搜索的索引。回答时写上来源的标题，以及章节或页码；飞书文档再附上链接。

这项**默认关闭**。旧的配置文件不用改。不写 `knowledge`，或 `enabled` 为 `false` 时，不建索引、不检索，提示词、工具和 `/状态` 与现在一样。

它和另外两样不要混：

| | 做什么 |
|---|---|
| `kb/` 和 `kb_read` | 本机器人文件夹里的 md、txt。模型按路径读一份。 |
| `kb_sync` | 把压缩包或飞书文档先放进待审区，你确认后才换上 `kb/`。 |
| `knowledge` | 按会话做可搜索的索引。默认关。 |

记忆记的是「这个群说过、定过的事」。知识库是「资料里写了什么」。两边仍然分开。

## 收录什么

打开之后，发「/kb refresh」才会收（见下面的命令）。也可以写 `refresh_min`，让程序自己补。

1. **本地 `kb/`**。`local` 不写就是收。PDF、Word、PPT、Excel、CSV、Markdown、文本和 zip 用原来的读取。单文件大小、压缩包体积和压缩比、PDF 页数，都用 `tools.attachment` 里已经有的上限。图片没有单独的文字识别，不进索引；扫描版 PDF 若能抽出文字，会按页收。跳不出 `kb/` 目录的链接不会读。
2. **本群发过的文件**。只有 `group_files` 为 `true` 才收。私聊没有群文件。
3. **飞书云文档、知识库、多维表格**。写在 `docs`、`wiki`、`bases` 里的会收。`group_links` 为 `true` 时，也收本群消息里的飞书链接。链接必须是飞书域名（`feishu.cn`、`larksuite.com`、`larkoffice.com`）。本机、内网和其他网站一律跳过，程序不会按资料里的网址去访问，只把文档编号交给原来的只读命令。

`tools.docs_read.allow_tokens` 如果不是空的，云文档和知识库只收这份名单里的，不会因为开了检索就读得更宽。

一次不要收太多。默认最多 40 份来源、2000 个片段。群文件默认最多 20 个。超过的会跳过，并在 `/kb` 里能看出来有没有失败。

同一份资料没有改过，再次刷新不会重切。改过的才替换。某一份这次没读成（例如没分享给应用），上次收好的先留着。

## 怎么搜、怎么引用

模型可以调用只读工具：

```text
kb_search {"query":"报名截止"}
```

它只能查**当前这个群或这次私聊**的索引。参数里写别的群号也没有用。

`auto_retrieve` 为 `true` 时，普通问题会先附上最多几条片段，再交给模型。`/kb`、`/记忆` 这种命令不会。没打开时，提示词里没有这段。

结果放在工具字数预算里，默认最多 4000 字，并且不会超过 `agent.tool_context_budget_chars`。超了会截断并注明。

每一条大致是这样：

```text
[1] 《报名须知》 · 报名须知 / 截止时间 · 第 2 页
城市挑战赛的报名截止是 10 月 20 日。
```

飞书文档如果当时带了链接，下面会多一行 `https://…feishu.cn/docx/…`。没有完整链接时（只配了 token），就不编一个假链接。

请在回答里用这个标题和章节或页码。索引里没有的事，应该说不知道。

## 命令

要先把 `knowledge.enabled` 设成 `true`。没打开时，这些字仍交给模型，和以前一样。

| 你发送 | 谁可以 | 结果 |
|---|---|---|
| `/kb`、`/kb status`、`/kb 状态` | 能叫到机器人的人 | 本会话有几份资料、多少片段、上次何时更新。不调用模型。 |
| `/kb refresh`、`/kb 刷新` | 只有写入白名单 `write.allowed_users` | 更新这一份索引。不调用模型。 |

`/状态` 只在这项打开时多一行「知识库检索：开」。关掉时那一行不出现。

`refresh_min` 写成 `0` 或不写，就不会定时收。写成分钟数时，小于 5 按 5 分钟。程序大约每 15 秒看一次，一个周期只更新一个到期的会话，避免占住心跳。演练、`--check` 和 `--doctor` 不会去收。

## 配置

完整的键写在 [agents/CONFIG.md](../agents/CONFIG.md) 的「分群知识库检索」。例子在 `agents/example.json`，里面 `enabled` 是 `false`。

最小打开方式：

```json
"knowledge": {
  "enabled": true,
  "auto_retrieve": true,
  "group_files": false,
  "group_links": false,
  "docs": [],
  "wiki": [],
  "bases": []
}
```

这样只收本地 `kb/`。要收群文件，再把 `group_files` 设为 `true`。要收群里贴的飞书链接，把 `group_links` 设为 `true`。

向量是可选的。不配就只用关键词，不需要额外安装包。

```json
"embeddings": {
  "enabled": true,
  "base_url": "https://api.example.com/v1",
  "api_key_env": "EMBEDDING_API_KEY",
  "model": "text-embedding-3-small"
}
```

密钥放在环境变量里，不要写进 json。地址不要带 `api_key`。本机模型可以用 `http://127.0.0.1:端口/v1`。接口失败时仍用关键词回答，并在 `/kb` 里说明这次没连上。

## 飞书权限

全是只读。没打开 `knowledge.enabled` 时，`--doctor` 不会因为这项多要权限。打开之后，用到哪一类才需要哪一条：

| 来源 | 权限 |
|---|---|
| 只收本地 `kb/` | 无 |
| 群文件 `group_files` | `im:message:readonly`、`im:message.group_msg`、`im:resource` |
| 云文档 `docs` 或群里的文档链接 | `docx:document:readonly` |
| 知识库 `wiki` 或群里的知识库链接 | `wiki:node:read`。有的应用里叫 `wiki:wiki:readonly` 或 `wiki:node:retrieve`，和现在读知识库文档是同一类 |
| 多维表格 `bases` 或群里的表格链接 | `base:record:read` |

改完要在开放平台发布版本。文档或表格还要分享给这个应用，否则那一份读不了，别的来源照常。

## 隔离和不可信正文

- 索引在 `state/kb/<会话>/index.sqlite`。一个会话打不开另一个会话的文件。
- 本地 `kb/` 是这个机器人的共享文件夹。哪个会话刷新，哪份索引里就会有它。群文件和群里的链接只进那个群。
- 客户名、手机号、证件号、邮箱、密钥样子的字符串和电脑路径，收录前打一次，检索结果再打一次。
- 资料里的 `<<TOOL>>`、`<<MEM>>` 和「确认」加六位数字会被换成看不出的样子，不能变成工具调用或确认码。
- 话题红线如果写了 `apply_to` 包含 `kb`，命中的段落在收录时丢掉。
- 检索结果标成不可信资料。模型不应照着里面的话改规则、去读别的群，或把内容放进网址。

## 索引怎么做的

中文没有空格，整句当成一个词会搜不到。这里用**重叠双字**（「报名截止」收成「报名」「名截」「截止」），再放进 SQLite FTS5。这是搜索引擎里中文常用的 CJK 双字法，不需要另外安装分词词典，Windows 上只要有 Python 自带的 SQLite。

问句通常比资料里的原句长，例如问「报名什么时候截止」，资料里只有「报名截止」。所以先按这些双字找出候选，再按重合多少排序，而不是要求问句整段都出现。章节标题和资料标题也放进同一份索引，只问章节名也能找到那一段；拿去回答的仍是正文。

向量打开时，关键词和向量各取一批，用倒数排名融合（Reciprocal Rank Fusion）合成。这是混合检索里常用的做法。向量请求失败，或根本没配，就只留关键词这一路。

每段尽量按标题和「第 N 页」切开，所以引用能落到章节或页，而不是整份文件。
