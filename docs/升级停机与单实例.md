# 升级说明：优雅停机和单实例锁

这一版不改配置也能接着跑。旧的 `state\bot.lock` 只有一行进程号，仍然认。`scripts\stop.ps1` 仍然只结束命令行和创建时间都对得上的本目录进程。

## 配置

| 键 | 不写时 | 写成 0 | 说明 |
|---|---|---|---|
| `shutdown_wait_sec` | 15 秒 | 收到停止信号后不等正在答的题 | 放在配置最外层，和 `catchup` 并列。负数或写错按 15 秒。 |

不用把原来的 JSON 改掉。想少等就加上 `"shutdown_wait_sec": 0`。

不要把 `app_secret` 或任何密钥写进配置。

## 停和启

`scripts\stop.ps1` 确认是本目录的 `agentbot.py` 之后，先写 `state\shutdown.request`，大约每秒再核对一次，最多等 20 秒。进程自己退出就不再强行结束。到点仍是本机器人，才走原来的 `Stop-OwnedTree`。

下面几种情况都不会结束那个进程：

- `bot.pid` 里的编号已经是别的程序
- 等待期间这个编号被换到了别的程序
- 命令行里没有本目录的 `agentbot.py`
- 旁边那个机器人的文件夹只是名字更长（例如 `C:\bots\bot` 和 `C:\bots\bot2`）。路径必须整段对上，不能只看前缀。不要把一个机器人的文件夹放进另一个机器人的文件夹里面。

无论是否结束进程，都会清掉本目录的 `bot.pid`、`state\bot.lock` 和 `state\shutdown.request`。

`scripts\start.ps1` 发现本目录已经在跑就直接退出，这时不会删掉 `shutdown.request`。只有真正要启动新进程时才删。`conflict_pidfiles` 里的编号如果已经是记事本之类的别的程序，不再因此拒绝启动，也不会结束它。读不到命令行时仍然拒绝启动。

看门狗发现心跳过期时，仍是先 `stop.ps1` 再 `start.ps1`，所以也会先走优雅停止。

## 没答完的题

正在答的题在 `state.db` 里是 `received`。优雅停止如果这题还没写完，不会把它改成已回答。进程被强行结束后也一样。下次启动先补答这一条，回复开头写「（延迟回复）」。同一条已经补过一次仍失败，就放弃。

`state\inflight.json` 只给排查用，里面是消息编号、阶段和开始时间。不写问题原文。阶段文字会打码手机号、证件号、邮箱和本地路径。

## 锁文件

第一行仍是进程号，给只读第一行的脚本用。后面多了两行：

```
12345
created=进程创建时间
base=本机器人的目录
```

创建时间对不上，说明这个编号已经分给了别的进程。这时不当成自己还活着，也不去结束那个进程。
