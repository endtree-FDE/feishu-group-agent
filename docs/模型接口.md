# 模型接口

回答从哪一家模型来，由配置最外层的 `model_provider` 决定。要换成 OpenAI 兼容接口或 Claude，也可以写 `model` 这一段，见 [换模型.md](换模型.md)。没写时仍是 Cursor。

没写这一项，就是 `cursor`，和以前一样。工具（`<<TOOL>>`、白名单、确认码）、技能、记忆、脱敏对每一种都一样。

## 怎么换成自己的账号

在这个机器人的 JSON 里改两处：

```json
"model_provider": "openai_compat",
"agent": {
  "model": "deepseek-flash",
  "base_url": "https://api.deepseek.com",
  "api_key_env": "DEEPSEEK_API_KEY"
}
```

- `base_url`：这家的 OpenAI 兼容地址，不要在后面自己加问号或密钥。
- `model`：这家控制台里的模型名。
- `api_key_env`：环境变量的名字。程序只从这里读密钥。

改完要停掉正在跑的进程，再启动。只改文件、不重启，旧进程还是旧的。

也可以不手写地址，把 `model_provider` 写成下面的预设名。三个空着的字段会补上：地址、模型名、环境变量名。已经写在 `agent` 里的值保持不动。`model_provider` 仍是 `cursor` 或没写时，预设不生效。

```json
"model_provider": "deepseek"
```

预设还有 `dashscope`（通义千问）、`zhipu`（智谱）、`pangu`（华为云 MaaS 上的盘古，OpenAI 兼容地址）。也可以保持 `model_provider` 为 `openai_compat`，另写 `"preset": "deepseek"`，效果一样，而且你写上的 `base_url` 或 `model` 会盖过预设。

openJiuwen / JiuwenSwarm 不另占一个预设。比赛给你的 `API_BASE`、`MODEL_NAME` 填进 `base_url` 和 `model`，密钥放进环境变量，变量名写在 `api_key_env`。字段对照和仍然有效的确认码见 [用本框架参赛.md](用本框架参赛.md)。

`stall_sec`、`max_runtime_sec`、`network_retries` 仍然有效。卡住或到总时长时，已经写出的文字会先发出去。网络中断会按 `network_retries` 重试。401 不重试。

## 怎么放密钥

密钥只放在运行这台程序的环境变量里。不要写进 JSON，不要写进日志，不要贴到聊天里。

配置里写的是变量名，例如 `DEEPSEEK_API_KEY`。程序报错时也只提这个名字和 HTTP 状态码，不把密钥打出来。

## Windows 上怎么设环境变量

先开一个 PowerShell。把下面的名字换成你的变量名，把引号里换成你的密钥。这一窗口里马上生效：

```text
$env:DEEPSEEK_API_KEY = "你的密钥"
```

想让以后新开的窗口也有，再执行一次（当前这个窗口不会因此更新，要新开一个）：

```text
setx DEEPSEEK_API_KEY "你的密钥"
```

用 cmd 而不是 PowerShell 时，只对当前窗口有效：

```text
set DEEPSEEK_API_KEY=你的密钥
```

设好之后，用**同一个窗口**启动机器人，它才看得到。

本地 Ollama 不校验密钥，但这里仍要求变量非空。放一个占位即可，例如 `ollama`。

## 怎么确认生效

在放着 `agentbot.py` 的目录里：

```text
python agentbot.py agents\你的机器人.json --check
```

`openai_compat` 成功时有一行 `OK   openai_compat`，里面有变量名和模型名，没有密钥的值。变量没设是 `FAIL openai_compat`，并且写着「未设置」。密钥错了一般是 `HTTP 401`。

然后再到一个不重要的群里问一句。日志 `logs/bot.log` 里应有 `model provider openai_compat`。

## 和 cursor 的差别

Cursor 那一路能读知识库里的文件、能搜索、能看网页，也能按工作区里的图片文件看图。`openai_compat` 没有这些。它只看见程序拼进提示词的文字。

所以：

- 知识库文件不会自动读出来。提示词里没写上的段落，它看不到。
- 图片附件它看不到内容，只能看到「用户发来一张图片」这句说明。
- 没有常驻进程。`agent.mode` 写成 `acp` 对这一路不起作用。

飞书仍然只通过 `<<TOOL>>` 来查和写：群历史、文档、日历、表格、确认码，以及 `skill_read`，和 cursor 时一样。写操作还是要白名单和 6 位确认码。

## 怎么切回 cursor

把 `model_provider` 改回 `cursor`，或者删掉这一项。停掉进程再启动。

环境变量可以留着，cursor 不用它。日志里应是 `model provider cursor`，不应再出现 `openai_compat`。
