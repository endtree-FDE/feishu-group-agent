# 复盘写回

一轮群里的事做完之后，机器人可以写一句短复盘：做了什么、哪里出错、下次怎么做。这句话先变成一条记忆提案。审批人回复「确认记忆」之后，才写入**这个群**的长期记忆。不回复、驳回、过期，都不写。

这项**默认关着**。配置里没有 `memory.retrospect`，或 `enabled` 不是 `true` 时，答完不会提议，也不改已有记忆。

## 怎么开

主人在和机器人的私聊里发「设置」，找到「复盘写回」。打开时会把长期记忆一起打开，否则记不住。

审批人用的是记忆成长那一份名单：`memory.growth.approver_open_ids`。名单空着，或还是 `REPLACE_` 占位时，不会提议。提案默认私聊发给审批人。`memory.growth.deliver` 写成 `group` 时，发在被复盘的那个群，不发到别的群。

长期记忆本身也要开着（`memory.enabled` 为 `true`）。只写 `memory.retrospect.enabled` 而不开长期记忆时，不提议。

## 什么时候写

- 只处理群聊。私聊里的对话不写进群记忆。
- 这一轮用过工具或技能，或者有人说「做完了」「完成了」「结束」，才写。普通寒暄不写。
- 同一个群已经有一条还没处理的复盘时，不再叠第二条。
- 不另外调用模型。句子由这一轮的步骤拼出来：成功的技能和工具、失败的步骤、一句下次怎么做。
- 调用记录关着时，这一轮的步骤仍会在内存里用完就丢掉，复盘照样能写。`logs/calls.jsonl` 里仍然不放群号。

## 点头之后

审批人处理的口令和记忆成长相同：

```text
确认记忆 123456
改记忆 123456：新的一句
驳回记忆 123456
```

确认码只认审批人本人，并且要在送达的那个会话里回复。私聊送达时，在群里回复不算。发到 A 群时，拿到码去 B 群回复不算，也不会写入 B 群。

写入的是这个群自己的 `facts.jsonl`。别的群的账本不动。

## 脱敏

写入提案之前先脱敏。客户名变成「某客户」，手机号、邮箱、密钥和本机路径不留原文。脱敏之后仍有不能记的内容，这一条不提议。

## 不做什么

- 不新开收消息进程，也不为这项再订阅事件。
- 不把复盘发到别的群，也不在没人点头时改记忆。
- 不因为打开这项就去改技能文件。
