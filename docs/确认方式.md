# 确认方式

新建文档、追加文档、建日程、改日程、删日程、往表格加记录，以及在私聊里改功能开关，都要先确认。确认不能关掉。没确认之前，飞书上的东西不会被改。

旧的配置文件不用改。没写下面这些键时，按点按钮来。飞书应用还没开通卡片回调时，自动改回确认码。

## 你能看到什么

默认会发一张卡片，上面用白话写三件事：

- 要做什么
- 改哪里
- 影响谁

卡片上有两个按钮：「确认」和「取消」。只有发起的那个人本人点了才算。别人点了没反应，这次操作也不会被用掉。

点完之后，这张卡片变成「已确认」或「已取消」，机器人再回复做成了没有。

按钮默认 10 分钟内有效，过了就要重新发起。点过一次就不能再点。

## 功能开关那张卡片

主人私聊发「设置」时，用的是另一张卡片，步骤见 [新手开关功能.md](新手开关功能.md)。

点某一行的勾选不会马上写入。原来那张卡片换成「确认开启」「确认关闭」或「确认这 N 项」，旁边是「取消」。点确认才走上面这套核对、备份和重启。点取消只把卡片换回清单。可以一次勾几项，只确认一次。再点已经勾上的那一项，会把它从待确认里撤下。

飞书没开通卡片回调，或者这项确认方式是纯确认码时，不发这张交互卡片，改发一条短文字，回复序号。回复数字时，确认仍是另外一条消息，和别的写入一样。

## 四种方式

写在配置的 `confirm` 里。主人也可以在和机器人的私聊里换，见下面一节。

| `confirm.mode` | 怎么确认 |
|---|---|
| `button` | 只点按钮。这是默认。回复数字不算。 |
| `code` | 只认确认码。机器人发一串数字，发起人回复「确认」加这串数字，或「取消」加同一串数字。 |
| `button_or_code` | 点按钮或回复确认码，做一样就行。 |
| `button_and_code` | 两样都要。先点还是先回复都可以。取消只要一样。 |

批量建日程、改功能开关、重启，可以用 `confirm.high_risk_mode` 单独指定上面四种里的一种。不写时，和 `confirm.mode` 一样。

确认码默认 6 位、5 分钟有效，和以前相同。要改的话：

| 键 | 作用 |
|---|---|
| `confirm.code_digits` | 位数，只接受 4 到 8。不写是 6。 |
| `confirm.code_ttl_sec` | 确认码有效秒数。不写时用 `write.confirm_ttl_sec`（不写则是 300）。 |
| `confirm.ttl_sec` | 按钮有效秒数。不写是 600。 |
| `confirm.card_callback` | `auto`（默认）、`on`、`off`。见下面一节。 |
| `write.confirm_ttl_sec` | 以前就有的确认码秒数。没写 `confirm.code_ttl_sec` 时仍用它。 |

写成关掉、`off`、`none` 或 `false`，程序仍按点按钮处理。不会出现「不用确认」这一种。

## 在私聊里换

主人打开和机器人的私聊，回复「确认方式」，会看到现在选的是哪一种、实际在用哪一种。

想换，回复其中一句：

```text
确认方式 点按钮
确认方式 确认码
确认方式 都可以
确认方式 都要
```

「都可以」是点按钮或确认码。「都要」是两样都要。换的时候同样要先确认，确认后机器人会重新启动。白名单不在这里改。

回复「关掉确认」不会生效。

## 什么时候会退回确认码

下面几种情况，即使你选的是点按钮，也会先用确认码：

- 飞书应用还没订阅「卡片回传交互」（`card.action.trigger`）
- 长连接明确报了没有权限，或不认识这个事件
- 卡片没能发出去
- `confirm.card_callback` 写成 `off`

退回之后，发起人会看到原来的那句「确认」加数字。开通卡片回调之后，不用改配置，下一次写入会自己改回点按钮。

没订阅时，程序不会反复重启卡片接收进程，也不会把收消息的长连接判成断线。私聊只提醒主人一次，说明怎么开通。断线提醒仍只在收消息的长连接真的断了之后才发。

断线、超时、连接被关掉，不当成「没有权限」，也不会因此关掉按钮。卡片进程自己退出，也不算机器人断线。

## 要不要启动卡片进程

`confirm.card_callback` 不写是 `auto`。

| 值 | 行为 |
|---|---|
| `auto` | 启动前先探测。明确没订阅就不起这个进程，这次运行也不再重启。确认改用确认码。 |
| `on` | 总是去启动。若退出原因是没订阅（`failed_precondition`、`not subscribed` 或退出码 2），这次运行不再重启。 |
| `off` | 不启动。确认用确认码。 |

## 开通卡片回调

不需要公网地址，也不用自己架服务器。回调走已经在用的 `lark-cli` 长连接。

1. 打开飞书开放平台，进入这个应用的「事件与回调」。
2. 订阅方式选「使用长连接接收事件」。
3. 添加事件「卡片回传交互」（`card.action.trigger`）。
4. 发布版本。

然后在你自己的电脑上执行：

```text
python agentbot.py agents/<你的配置>.json --doctor
```

这条命令不发消息。卡片回调还看不出来或本机记下没开通时，会有一行 `WARN`，并写着上面的开通步骤。已经连上时，这一行是 `OK`。`WARN` 不会让诊断失败。没开通时，接收进程数量不含 `card.action.trigger`，这不算断线。

## 程序怎么防别人代点

卡片上只带一个一次性记号，和这次动作的校验值。真正要执行的命令留在你这台电脑上。

点下来之后，程序核对这几样，对不上就不执行，也不把这次操作用掉：

- 点的人是不是发起人
- 是不是原来的会话
- 话题对不对（卡片没带话题时，只要人和会话对得上）
- 校验值是不是提议时记下的那一个（卡片内容被改过就不算）
- 有没有过期
- 这张卡片是不是当时发出去的那一张（平台返回了消息编号时才核对）

用过、取消过的记号会先记下来，再执行。重启之后也不能再点一次。

确认码仍只认发起人、原来的会话和原来的话题。发错的人不会把码用掉。

## 日志

写入审计在 `audit/` 目录。里面不写确认码、按钮记号，也不写人的编号，只留它们的短哈希。客户名仍按你的名单打成「某客户」。

功能开关的日志仍在 `logs/feature_switch.jsonl`，同样不写确认码和编号。
