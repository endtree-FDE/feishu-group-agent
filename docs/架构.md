# 飞书群智能体 · 长期记忆 + 技能层 · 架构说明

> 这是设计说明。下面走一遍「一条消息怎么被回答」时，用的都是编出来的例子：人叫小李、小王，机器人叫示例助手，活动叫城市挑战赛。不是真实记录。
> 配图源文件就在本目录：`arch-full.mmd`（整体架构）、`memory-flow.mmd`（记忆怎么记下来）。用能看 Mermaid 的编辑器打开。
> 模型名字写在每个机器人自己的配置里。默认是本机 Cursor 的 `grok-4.7-high-fast`。也可以换成 OpenAI 兼容接口（DeepSeek、通义、智谱、盘古，或比赛给的地址），密钥只放在环境变量里，见 [模型接口.md](模型接口.md)。

## 0. 结论先说

1. **记忆分四层，全部存成纯文本文件，不引入付费服务：**
   - 短期：本话题最近 N 轮对话，现在已经有了；
   - 工作摘要：每个话题一段压缩小结；
   - 长期事实：分群和分人存，记“谁是谁、定了什么、截止哪天、偏好”；
   - 情景日志：每天一份流水。
   这个分法综合了 OpenClaw、CowAgent 的 `MEMORY.md + memory/日期.md`，以及 My-agent 的三层记忆。
2. **写记忆有三条路：**
   - 用户说“记一下”，立即写入（最可靠）；
   - 回答时模型顺手输出一行 `<<MEM>>`，零额外调用（借鉴 LangMem 的 hot path）；
   - 每晚整理一次，做过期、合并、重写档案（借鉴 OpenClaw 的 dreaming 和 CowAgent 的 Deep Dream）。
   冲突时不覆盖，把旧条目标成“已被取代”、保留历史（借鉴 Graphiti 的时间有效期）。
3. **注入要便宜：**每题只塞“群档案 ≤800 字 + 提问人档案 ≤400 字 + 话题摘要 ≤300 字 + 关键词命中的 3–5 条事实”，读本地文件只需毫秒级。档案在一个常驻会话里冻结成快照不变（借鉴 Hermes），这样 prompt 缓存能命中，不拖慢速度。
4. **技能层**按渐进披露：`skills/<名字>/SKILL.md`，提示词里只放一行「名字：描述」。YAML 头可以选填 `triggers`。问题命中时，最多把得分最高的那一份正文（脱敏后，有字数上限）预先放进这一题会变的部分，省掉一轮 `skill_read`；没命中才由模型输出 `skill_read` 再读。`skills.enabled` 默认关。怎么写见 [技能.md](技能.md)。
5. **四样东西分工清楚：**知识库是“世界的资料”，记忆是“我们群说过、定过的事”，技能是“某类事怎么做的步骤”，工具是“动飞书的手”。写操作仍然一律走白名单 + 6 位确认码。
6. **隐私与内容策略贯穿全程：**写入前、注入前、展示前各过一次 guard。固定做的是客户名和个人敏感信息脱敏（redact.txt）；其他“不谈什么话题”的红线**框架不内置**，由每个机器人在配置 `policy.redlines` 里自定，默认为空（示例助手、另一助手都为空）。项目之间的隔离靠每个机器人自己的配置和每个群自己的记忆、知识库，不靠屏蔽词。任何人都能用 `/记忆` 查看、用 `/忘记` 删除自己的记忆，删除是真删。
7. **一个机器人一份配置**：`agents/<名字>.json` + 人设（写在 system_prompt 里）+ `redact.txt` + 选装的 `skills/`。记忆目录按机器人、按群隔开。

## 1. 架构图

现在一条消息实际走的路见 [arch-now.mmd](arch-now.mmd)。两条模型都经过同一套门卫、工具确认和出口脱敏。`cursor` 可以自己翻工作区里的文件。OpenAI 兼容接口只看见程序拼进提示词的文字，知识库正文要靠程序代读。

收消息、发消息、改卡片、读历史和查成员走渠道适配器。没写 `channel` 时适配器是飞书，lark-cli 的命令和以前一样。缺能力时核心降级，不改确认码和脱敏。图和说明在 [渠道.md](渠道.md)，企业微信的接口选择在 [渠道-企业微信.md](渠道-企业微信.md)。

只读工具可以连续多轮，轮数是 `agent.max_tool_rounds`（不写是 4）。每一轮按顺序执行多条只读调用。历史里出现的当前会话附件用 `message_attachment` 读，可以一次传多个消息编号；下载前后都核对会话。写操作仍然提议一次就停，等 6 位确认码。`--doctor` 是运维诊断，不在这条回答路径上，也不发消息。`logs/events.jsonl` 和 `logs/journal.jsonl` 都在本机，都不记问题原文。`logs/calls.jsonl` 记每轮调用链，写入前脱敏，默认开，见 [调用记录.md](调用记录.md)。每晚重写记忆仍是设计，默认不跑。

[arch-full.mmd](arch-full.mmd) 是分层设计图。第⑤层已经画成「Cursor 或 OpenAI 兼容」二选一。图里的第⑨层（每晚整理记忆、知识库流水线）和第 0 节里的情景日志，仍是设计，默认不跑，不要当成已经打开的功能。记忆从「记下来」到「下次用上」见 [memory-flow.mmd](memory-flow.mmd)。

一句话读图：消息从①进来，②决定答不答，③认出是哪段对话并亮出“处理中”，④拼一份小抄，⑤模型思考、按需翻技能和知识库，⑥需要时动飞书（写操作要确认），⑦说出去之前再查一遍、说完再记，⑧所有东西都存成本地文件，⑨后台每天同步知识库、整理记忆，⑩一份配置决定以上每层怎么表现。

## 2. 新手导读：跟着一条消息走一遍（可以一小节一小节地讲）

**例子**：10 月 17 日下午，小李在示例助手群的一个话题里发：

> @示例助手 城市挑战赛 报名进度怎么样了，上次我们定的截止是哪天？

（下面的档案、事实、表格内容都是为了把流程讲清楚而编的例子，不是任何人的真实记录。）

这句话其实问了两件事：“现在进度如何”（要查最新数据），以及“上次定的截止”（要回忆过去的决定）。后者正是长期记忆要解决的问题。

### 第 1 步 · 消息进门（①飞书接入层）
- **发生了什么**：飞书服务器把这条消息作为一个“事件”推给运行电脑上的 lark-cli。lark-cli 和飞书之间保持着一条一直不断的连接（长连接），所以消息一来就能收到，不用定时去问。
- **收到的内容**：消息编号、群编号（chat_id）、发送人编号（open_id）、话题编号（root_id）、正文、@ 了谁。
- **为什么要有这一层**：机器人得有“耳朵”。长连接的好处是不需要公网服务器和域名，家用电脑也能跑。

### 第 2 步 · 门卫检查（②门卫与路由层）
- **发生了什么**：按顺序检查：
  1. 这条消息处理过没有（去重：飞书偶尔会重复推送）；
  2. 是不是 @ 了我，或者是私聊；
  3. 这个群能不能回答：配置了 `chat_ids` 就只认这份名单；名单是空的并且打开了自动认群时，还要过安全门槛（默认要白名单成员发过「/认群」）；
  4. 这个人是不是问得太频繁（限流）；
  5. 现在同时在答的是不是已经 2 题了（并发上限，多的排队）。
- **为什么**：没有门卫，机器人会重复回答、在不该说话的群说话、被人刷屏，还可能把电脑跑满。

### 第 3 步 · 红线预检
- **发生了什么**：问题里出现客户名（redact.txt 里的词），先替换成“某客户”。如果这个机器人的主人在配置里设了内容红线（`policy.redlines`，默认为空），命中 `action: refuse` 的问题就礼貌拒答，后面的步骤都不走。
- **为什么**：隐私和红线越早拦越省事。拦在入口，后面的记忆、日志、卡片里就都不会出现敏感内容。具体拦哪些话题因客户而异，所以做成配置，不写死在框架里。

### 第 4 步 · 路由：这是简单题吗？
- **发生了什么**：
  - `/help`、“你能干什么”、`/记忆`、`/忘记 3`、自动认群的 `/认群` 和 `/忘群` 这类命令和能力问答，直接用现成文字回复（捷径），不惊动模型；
  - 我们这题要查资料、要回忆，所以走“需要思考”这条路。
- **为什么**：模型思考最慢（十几秒到几十秒），能不用就不用。

### 第 5 步 · 找到“这段对话”（③会话层）
- **发生了什么**：用“群 + 话题 root_id”算出一个会话键；私聊则用发送人的 open_id。之后读这段对话最近 6 轮问答，现在存在 `state.db`。
- **为什么**：同一话题里接着问“那负责人是谁”，机器人得知道“那”指什么。不同话题互不串台（botmux 也是“一个话题 = 一个会话”）。

### 第 6 步 · 先让人知道在干活（③进度层）
- **发生了什么**：立刻在小李的消息上贴一个“处理中”表情，再发一张卡片，显示“正在理解问题…”。
- **为什么**：用户最难受的是“没反应”。2 秒内给信号，后面多等十几秒也能接受。进度卡片就是干这件事的，要在配置里把 `progress.enabled` 设成 true 才出现。

### 第 7 步 · 拼一份“小抄”（④上下文拼装层）
- **发生了什么**：模型本身什么都不记得，每次都要把它需要知道的东西写进一段输入文字里，这段文字就叫 prompt。拼装器按固定顺序、在固定字数预算内拼好：

| 顺序 | 内容 | 例子 | 预算 |
|---|---|---|---|
| 1 | 人设 + 规则 | “你是示例团队团队的助手示例助手……不提客户名……先说结论”（加上该机器人在 `policy.redlines` 里配置的规则，没配就没有） | ~600 字（不常变） |
| 2 | 技能目录 | “查进度表：查/更新团队进度表时用；写会议纪要：……”（每个技能一行） | ≤ 500 字（不常变） |
| 3 | 知识库目录 | “deadlines_1016.txt：各赛事截止日汇总（10-16）；F_一页纸.md：团队一页纸介绍……” | ≤ 1000 字（每天变一次） |
| 4 | 工具说明 | 只列已开权限的工具 | ~400 字 |
| 5 | 群档案 GROUP.md | “成员：小王（负责人）、小李（运营）……；进行中：城市挑战赛（AI+营销赛道）……” | ≤ 800 字 |
| 6 | 提问人档案 USER.md | “小李：喜欢先看结论、要表格” | ≤ 400 字（需开启按人记忆） |
| 7 | 命中的事实 | “[决定 · 10-16 群聊] 城市挑战赛 报名截止按 10 月 20 日；材料由小李汇总” | 3–5 条 |
| 8 | 话题摘要 + 最近 6 轮 | “本话题在讨论 城市挑战赛 报名材料……” | ≤ 300 字 + 6 轮 |
| 9 | 本次问题 | “城市挑战赛 报名进度怎么样了……” | – |

当前代码还没有知识库目录。技能目录默认关着；打开之后放在工具说明之后、群档案之前，预算默认 800 字，不是上表里的第 2 块。触发词命中时，正文不进这一块，而是放在本次问题前面（有对话历史或工具结果时放在它们后面），所以目录和群档案这两段稳定前缀不会因为这一题换技能而改字。

- **为什么排这个顺序**：前 4 块很少变，放最前面，模型服务能复用上一次的计算结果（prompt 缓存），更快也更省。会变的放后面。
- **为什么要有预算**：小抄越长，模型读得越慢、越容易分心。预算保证无论群里聊了多少，小抄都不会膨胀。
- **“命中的事实”怎么挑**：从问题里抽关键词（城市挑战赛、截止、报名），和事实库逐条比对，按“关键词重合度 + 新近程度 + 是不是明确决定”打分，取前 3–5 条。全部在本地完成，耗时毫秒级。

### 第 8 步 · 模型思考（⑤模型运行层）
- **发生了什么**：小抄交给当前的模型接口。没写 `model_provider` 时就是 cursor-agent（配置里的模型，默认 grok-4.7-high-fast，只读）。默认 `agent.mode` 是 `oneshot`，每题新开一个 `-p` 进程。改成 `acp` 后进程只启动一次，同一话题复用会话。怎么开、怎么关见 [常驻模式.md](常驻模式.md)。写成 `openai_compat` 就改用你自己的 OpenAI 兼容账号，密钥在环境变量里，不进配置。这一路没有读文件和上网，飞书工具、技能、记忆、脱敏仍走原来的程序。怎么配见 [模型接口.md](模型接口.md)。模型发现：
  - “上次定的截止”小抄里已经有了（第 7 块的那条决定），不用翻资料；
  - “进度”要看最新数据。技能目录里「查进度表」的触发词对得上时，程序已经把正文放在这一题的问题前面，模型按步骤调用多维表格读取，不必再 `skill_read`。没有触发词、或 `skills.preload` 关掉时，仍是模型输出 `<<TOOL>>{"tool":"skill_read","name":"progress-table"}`，程序再读出正文。
- **为什么要有常驻模式**：每次新开一个进程，光启动就要 13–24 秒（已实测）。常驻进程只启动一次，之后每题省掉这段时间。默认仍是每题一个进程，已经在跑的机器人不用改配置。
- **为什么技能只放目录**：技能可能有十几个，每个全文几百到几千字。全塞进去小抄会爆，所以只放一行目录，用到才读全文，这就是“渐进披露”。

### 第 9 步 · 用工具查数据（⑥工具层）
- **发生了什么**：模型输出一行工具调用 `<<TOOL>>{"tool":"base_read",…}`。机器人检查这个工具开了没有、权限够不够，然后用机器人自己的身份去读多维表格，把结果交回模型。
- **如果是写操作**（比如“帮我把进度改成已提交”）：机器人不会直接执行，而是先生成一个 6 位确认码，必须发起人本人回复“确认 123456”才执行，并记审计日志。
- **为什么**：读，错了也没损失；写，错了会改坏团队数据，所以要三道锁（人在白名单、资源在白名单、本人确认）。

### 第 10 步 · 写答案并做出口检查（⑦出口层）
- **发生了什么**：模型写出：“结论：报名材料还差 2 项……；截止是 10 月 20 日（10-16 群里定的）。”这段文字再过一遍出口检查：客户名替换、去掉电脑路径和密钥样子的字符串；如果配置了 `policy.redlines`，再按规则删掉命中的段落。
- **为什么入口查了出口还要查**：模型可能从知识库或工具结果里带出敏感词，入口拦不到。

### 第 11 步 · 卡片定稿
- **发生了什么**：表情换成“完成”，这轮问答写进 `state.db`。卡片模式里，答案另发一条文字；默认把「处理中」卡片改成「已完成」。配置 `progress.delete_status_after_reply` 为 true 时，答案发出后撤回机器人自己发的那条状态消息，撤回失败才改成「已完成」。文字模式是把那条状态消息直接换成答案，这时不撤回。
- **为什么**：用户看到完整结果，下一轮追问也有上下文。撤回只去掉那条临时状态，答案本身留在群里。

### 第 12 步 · 记下来（⑦记忆写入器，后台进行）
- **发生了什么**：答案发出去之后，后台判断这轮有没有值得长期记的东西：
  - 小李如果说了“记一下：材料周五前交给小王”，就立即记一条“决定”，归在群名下；
  - 没有明确说，但模型回答时附了一行 `<<MEM>>{"type":"status","subject":"城市挑战赛","content":"材料还差 2 项","ttl_days":3}`（用户看不到这行），也记，但标为“自动”，3 天后过期；
  - 闲聊、问候、手机号这类内容一律不记；命中本机器人 `policy.redlines` 的内容也不记（默认没有）。
- **为什么放到后台**：记忆写入不能拖慢回答，用户已经拿到答案了，后面慢慢记。
- **为什么要标来源和过期时间**：进度这种事明天就变了，过期了还当真，就会误导人。

### 第 13 步 · 夜里整理（⑨后台流水线）
- **发生了什么**：每天凌晨跑一次：
  1. 把过期条目标成“已过期”；
  2. 合并重复的；
  3. 有冲突的（比如截止日改成了 10-22），旧的标成“已被取代”；
  4. 把今天的要点写进 `daily/2026-10-17.md`；
  5. 重写精简版 GROUP.md。
  前三个晚上先生成一份差异报告给人看，和知识库的 staging 一样。
- **为什么**：白天只追加不整理，保证写得快；晚上集中整理，保证档案始终短而准。

### 第 14 步 · 第二天再问
- 小王在另一个话题问“城市挑战赛 截止哪天？”。不需要翻任何资料，群档案里就有：“10 月 20 日（10-16 群里定的，小李汇总材料）”，几秒就能答。
- 小李私聊发“/记忆”，能看到和她有关的条目编号；发“/忘记 2”，那一条就被真的删掉。

## 3. 分层说明（每层：做什么 · 为什么 · 现在有什么 · 要新做什么）

| 层 | 做什么 | 为什么 | 现状（v2） | v3 新增 |
|---|---|---|---|---|
| ① 接入 | 收消息、下载图片和文件 | 机器人的耳朵 | lark-cli 长连接 + messages-mget/resources-download | 不变 |
| ② 门卫路由 | 去重、只认 @ 和私聊、群白名单、限流、单实例、并发、红线预检、捷径 | 防重复、防乱说、防刷屏 | 都有；能力问答已有捷径；技能触发词预判已做（`skills.preload`，只在技能层打开时生效） | 新增记忆命令：`/记忆`、`/忘记 N`、`/忘记全部`、`记一下 …` |
| ③ 会话进度 | 会话键、进度表情和卡片 | 接得上话、让人知道在干活 | 话题记忆（SQLite，6 轮，24h）；进度卡片代码已有、默认关 | 话题摘要文件；ACP 会话按话题复用 |

## 4. 记忆设计（详细）

### 4.1 作用域：谁的记忆、谁能看到

| 作用域 | 存什么 | 谁能看到或用到 | 默认 |
|---|---|---|---|
| 群（chat） | 成员和分工、项目、决定、截止、群规、群偏好（比如“回答要短”） | 只在本群的问答里注入；群成员用 `/记忆 群` 查看 | 开 |
| 话题（topic） | 本话题的压缩摘要 | 只在本话题注入 | 开（现在已有最近 N 轮，新增摘要） |
| 个人（user） | 本人的偏好、称呼、职责 | 默认只在本人私聊里注入；在群里只用“公开属性”（姓名、分工） | **关**（你之前定过“按人记忆先关闭”，需要你确认再开） |
| 情景日志（daily） | 每天的要点流水（谁问了什么类型的问题、做了哪些写操作、定了什么） | 只给夜间整理和“上周我们聊了啥”这类问题用，不常驻注入 | 开 |

**隔离规则**：私聊里说的事默认不进群记忆；A 群的记忆绝不进 B 群；不同机器人的记忆目录物理隔离（按 base_dir 分开）。

### 4.2 文件布局（运行电脑本地，每个智能体一份）

```
<base_dir>/memory/
  groups/<chat_id>/
    GROUP.md            # 精简档案（每晚重写，≤800 字），给人看也给模型看
    facts.jsonl         # 事实账本：只追加，状态靠字段表示
    topics/<root_id>.md # 话题摘要（≤300 字），14 天不活跃就归档
    daily/2026-10-17.md # 当日流水
  users/<open_id>/
    USER.md             # 个人档案（≤400 字）
    facts.jsonl
  _audit/memory-audit.jsonl  # 谁、何时、记了或删了什么（删除只留编号，不留内容）
  _staging/<日期>/      # 夜间整理的差异报告（前 3 晚人工看）
```

`facts.jsonl` 每行一条，例如：
```json
{"id":"g-0007","scope":"group:REPLACE_CHAT_ID","type":"decision","subject":"城市挑战赛","content":"报名截止按 10 月 20 日；材料由小李汇总","source":{"msg":"msg_example","by":"REPLACE_USER_OPEN_ID","at":"2026-10-16 19:02"},"how":"explicit","status":"active","valid_from":"2026-10-16","expires":"2026-10-27","supersedes":null,"last_seen":"2026-10-17"}
```
- `type` 只允许这几类：`person`（谁是谁、分工）、`decision`（定了什么）、`deadline`（截止）、`preference`（偏好）、`status`（进度，短期有效）、`rule`（群规）；P1 导入时另加 `project`（项目与进展）和 `resource`（资源链接）两类。P1 的事实另有 `short`（进 GROUP.md 的一句话）和 `uncertain`（待确认）字段。
- `how`：`explicit`（有人说“记一下”）、`auto`（模型顺手记的）、`import`（从知识库或人工导入）。
- `status`：`active`、`superseded`（被取代）、`expired`（过期）、`pending`（自动抽取还没生效）。

### 4.3 怎么写进去（三条路）

| 方式 | 触发 | 成本 | 可信度 | 默认 |
|---|---|---|---|---|
| 显式 | 消息以“记一下 / 记住 / 备忘”开头 | 0 次额外模型调用：在原答案里让模型规整成一条事实 | 高 | 开；群作用域只有写入白名单成员能写，其他人写进个人作用域（需要开个人记忆）或被礼貌拒绝 |
| 顺手（hot path） | 模型回答时发现“决定、截止、分工变化”，在末尾输出一行 `<<MEM>>{…}`（用户看不到，机器人截下来） | 0 次额外调用，只多几十个 token | 中 | 先“影子模式”：只写进 pending，一周后你看质量再决定是否转 active |
| 夜间整理 | 每天 03:00 计划任务 | 每群每天 1 次模型调用（用配置里的模型，可换低一档） | 合并后最高 | 前 3 晚只出差异报告，你点头后才自动生效 |

**规则先筛**：没有日期、人名、“定/决定/改成/负责/截止/以后都”这类词的问答，直接不进抽取，连 `<<MEM>>` 也不让输出（在提示里写明），这样噪音少、开销小。

已落地的可选做法见 [记忆成长.md](记忆成长.md)。`memory.growth` 默认关。打开后才在配置的时间或一段对话闲下来时提议新增、更新或作废；审批人确认之前不改账本。这不是上面表里「点头前只出报告、之后自动生效」的那一版。

### 4.4 去重、冲突、过期
- **去重**：同 scope、同 type、同 subject，内容的字重合度超过 80%，就只更新 `last_seen`，不新增。
- **冲突**：同 subject 的 `decision`/`deadline` 内容不同时，新的生效，旧的标 `superseded` 并记下取代关系。回答里能说“原定 10-20，10-18 改成 10-22”。借鉴 Graphiti 的“有效期”思路，但只用 jsonl，不上图数据库。
- **过期**：
  - `status` 默认 3 天；
  - `deadline` 在截止日 + 7 天后过期；
  - `decision`、`person`、`rule` 不自动过期，但 90 天没被用到时在夜间报告里提示“是否仍有效”；
  - daily 日志保留 30 天，之后浓缩成月度摘要。
- **上限**：每个群的 active 事实超过 200 条时，夜间整理按“用得少 + 旧”降级到日志层，借鉴 Hermes 的字数上限做法。

### 4.5 隐私和红线
1. **写入前**：`guard.redact()` 替换客户名（redact.txt）、手机号、证件号、邮箱、token；命中本机器人 `policy.redlines` 的整条丢弃（默认没有规则）；健康、财务、家庭等个人敏感话题不记（规则词表 + 提示约束）。
2. **注入前**：再过一遍 guard，防止 redact.txt 新增词以前已经写进去的内容漏出来。
3. **展示前**：`/记忆` 的输出和进度卡片同样过 guard。
4. **用户控制**（借鉴 ChatGPT“可查看、可删除、可关闭”）：
   - `/记忆`：私聊里列出与我有关的条目（编号 + 一句话 + 来源日期）；在群里只列群记忆前 10 条。
   - `/忘记 N`：删除第 N 条。本人能删自己的；群记忆只有写入白名单成员能删。**真删**：从 facts.jsonl 重写掉，审计里只留编号和时间。
   - `/忘记全部`：清空本人作用域（二次确认码）。
   - `/记忆 关`：本人退出个人记忆。
5. **不写的东西**：图片和文件原件不进记忆，只记“谁在某天发了某份材料（标题）”；工具返回的原始数据不进记忆。

### 4.6 怎么便宜地注入（速度）
- 读本地 md 和 jsonl 只要毫秒级；关键词打分用 Python 自带功能（字符二元组重合），**不需要向量库和新依赖**。
- 固定前缀（人设、规则、技能目录、知识库目录、工具说明）放最前，记忆包放后面，最大化缓存命中。触发词预放的正文算会变的部分，放在这一题的问题前面，不写进固定前缀，也不写进下面的冻结快照。
- `agent.mode` 为 `acp` 时，会话开始把当时的群档案冻成快照（借鉴 Hermes 的 frozen snapshot）。同一会话中途档案变了，下一问仍用开始时的那份；会话被丢掉、空闲超时或发了「新话题」之后，下一问才用新档案。`oneshot` 不冻结，每题都读当前档案。
- 总预算：记忆包 ≤ 1.5k 字（约 1k token），对首字时间的影响估计 < 1 秒【估计】。
- 以后要升级检索：先用 SQLite FTS5 全文检索（Python 自带，零成本），实在不够再加本地向量索引。两种都是可选项，不影响第一版。

## 5. 技能层设计

### 5.0 当前代码里已经有的

默认关闭。`skills.enabled` 为 false 时，提示词和没有技能层时一样，`skill_read` 也只是未知工具。打开后：

- 启动时扫描 `skills/<名字>/SKILL.md`。`name`、`description` 合法，且 `name` 与文件夹名一致，才进目录。`--check` 打印数量，格式不对的单独报一行。
- 每次拼提示词，在工具说明之后、群档案之前放目录：每个技能一行「名字：描述」，整段不超过 `skills.index_budget_chars`（默认 800）。同一次运行里这段不变。
- 模型输出 `<<TOOL>>{"tool":"skill_read","name":"名字"}`。`tools.py` 只读正文，名字必须在目录里，读出来再脱敏，然后让模型按步骤作答。步骤如果要求，还可以再调用一个已启用的飞书工具；写操作仍要确认码。
- YAML 头可以选填 `triggers`。`skills.preload` 默认 true，但只有 `skills.enabled` 为 true 才生效。问题命中时，最多预放 1 份正文（脱敏后，不超过 `skills.preload_budget_chars`，默认 3000 字），放在本次问题前面。命中多个时，按命中关键词的字数相加取得分最高的；得分相同用目录里靠前的。这段不进技能目录，也不进常驻会话冻住的群档案。没命中仍走 `skill_read`。
- 自带八份通用技能：`progress-table`（查进度表，只读）、`meeting-minutes`（整理会议纪要，不写入），以及六份创作流程（选题、口播、分镜、提示词包、策划书、复盘）。创作技能在用户明确要求保存时，才提议已有的写入工具，确认码不变。写法见 [技能.md](技能.md)。`agents/example.json` 里技能仍是关的。

还没做：用扩展字段限制技能能用哪些工具。在配置里点名只启用其中几个已经有了，键是 `skills.only`。

### 5.1 格式（遵循 agentskills.io 规范 + 我们的扩展字段）

`triggers` 选填，是一组关键词，用来做上面的预放。扩展字段（`x-tools`、`x-triggers`）当前不校验、也不使用。合法与否只看 `name` 和 `description`。
```
skills/
  progress-table/SKILL.md
  meeting-minutes/SKILL.md
  calendar/SKILL.md
  submission-check/SKILL.md      # 按需选装，不是每个机器人都要
  kb-search/SKILL.md
```
```markdown
---
name: progress-table
description: 查或更新团队进度表（多维表格）。用户问“进度/谁负责/截止/状态”或要求“改状态、加任务”时使用。
triggers: [进度表, 进度, 负责人, 截止, 谁负责]
x-tools: [base_read, base_create]     # 本技能允许用的工具（扩展字段，当前不使用）
x-scope: group,p2p
---
# 查进度表
1. 先用 base_read 读表（只取 任务/负责人/截止/状态 四列，最多 50 行）。
2. 回答格式：先一句结论，再列“未完成且 3 天内到期”的项，最多 5 行。
3. 用户要改：用 base_create 提案，按确认码流程执行；不要改别人负责的行，除非本人是写入白名单成员。
4. 表里没有的项写“表里没有”，不要猜。
```

### 5.2 懒加载怎么做

第 1、2、3 点已经按 5.0 做了（目录有总预算，默认 800 字；读取走 `skill_read`；触发词用的是 `triggers`，一题最多预放 1 份，多个命中取得分最高的）。第 5 点已用 `skills.only` 做了。第 4 点还没做。

1. 启动时扫描 `skills/*/SKILL.md`，只读 frontmatter，生成“技能目录”（每个技能一行）放进小抄。
2. 模型认为需要某个技能时，输出 `skill_read`，由程序读出正文再交回去。
3. **路由器预判（为了提速）**：问题命中某个技能的 `triggers` 时，机器人直接把正文预先放进这一题的问题前面，省掉一次读文件的往返（约 2–4 秒）【估计】。最多 1 份；命中多个时按关键词字数相加取得分最高的。正文有字数上限（`skills.preload_budget_chars`，默认 3000）。`skills.enabled` 为 false 时不做。
4. 技能里的“步骤”只能调用 `x-tools` 列出的工具，机器人执行时强制检查；写工具照旧走确认码。
5. 产品化：在 `skills.only` 里写名字列表，例如 `["topic-ideation","storyboard"]`，就只启用点到的技能。不写、`[]` 或 `false` 仍是全部。`agents/example.json` 里这项仍是 `[]`，并且 `skills.enabled` 仍是 `false`。

### 5.4 四样东西的关系

| | 知识库 kb | 记忆 memory | 技能 skills | 工具 tools |
|---|---|---|---|---|
| 是什么 | 世界的资料（规则、方案、研究） | 本群、本人说过或定过的事 | 某类事怎么做的步骤 | 动飞书的手 |
| 谁写 | 人审后 apply（kb_sync） | 对话中自动写 + 夜间整理 | 开发者或运营写，客户选装 | 代码写死，配置开关 |
| 多久变 | 每天一次 | 每题都可能变 | 很少变 | 很少变 |
| 进小抄的方式 | 目录常驻，原文按需读 | 档案常驻 + 命中的事实 | 目录常驻，全文按需读或预判塞入 | 说明常驻（只列开了的） |
| 冲突时以谁为准 | 官方事实以 kb 为准 | 团队内部决定以最新的记忆为准 | 流程以技能为准 | 权限以配置为准 |

## 8. 记忆和技能的测试题（上线前在 dry-run 里跑，上线后私聊再试）

**记忆**
1. 白名单成员发“记一下：城市挑战赛 材料周五前交给小王” → 回复“已记 #N”；`/记忆 群` 能看到。
2. 另一个话题问“城市挑战赛 材料什么时候交、交给谁？” → 答“周五前交给小王”，并带上来源日期。
3. 发“记一下：截止改到 10 月 22 日” → 再问截止 → 答 10-22，并说明“原定 10-20”。（冲突取代）
4. 非白名单成员发“记一下：……” → 群记忆不写，礼貌说明原因。
5. “记一下：某客户（用 redact.txt 里的名字）要求下周交付” → 落盘的内容是“某客户”，`/记忆` 里看不到原名。
6. （只在配置了 `policy.redlines` 的机器人上测）命中红线的“记一下：……” → 拒记；没配置红线的机器人照常记。
7. “记一下：我的手机号是 138…” → 手机号被丢弃或打码。
8. `/忘记 N` 之后再问相关问题 → 不再出现；facts.jsonl 里没有原文，审计只留编号。
9. 私聊里说的偏好，在群里问问题时不应被提起。
10. A 群记的事，在 B 群问 → 不知道。
11. 一条 `status` 类记忆 3 天后被夜间整理标成已过期，不再注入。
12. 问“上周我们定了哪些事？” → 从 daily 和 decision 里汇总，不翻知识库。

**技能**
13. 问“这周谁的任务快到期了？” → 用 progress-table，先读表，先说结论，列 ≤5 行，不改表。
14. “把刚才的讨论整理成纪要” → meeting-minutes 只整理成结论 / 待办 / 负责人 / 截止，不新建文档。
14a. “给青绿山水短视频出选题并打分” → topic-ideation 出表，不编播放量。用户没说保存就不提议写入。
14b. “写成 45 秒口播” → short-video-script 按秒分段，各段相加等于总时长。
14c. “列成分镜清单” → storyboard 五列：镜号、时长、画面、声音/音乐、AIGC提示词备注。
14d. “给这一镜写提示词，不要绑工具” → aigc-prompt-pack 正向和负向分开，工具对照写通用。
14e. “写一份项目策划书，截止没定” → creative-brief 九节，截止写未提及。
14f. “复盘这条成片，分镜返工了两次” → post-mortem 只引用用户给出的事实，不点名批评。用户要求存文档时才提议 docs_create，并等确认码。
15. “下周三下午 3 点约个评审” → calendar 先查冲突，再给确认码。
16. 另一助手发一个提交 zip（或目录截图）问“能交了吗？” → submission-check 逐项打勾，缺项标红。
17. 问知识库里没有的事 → kb-search 回答“待补”，不编造。

## 9. 需要你决定的事
1. **群记忆谁能写**：建议 = 写入白名单（示例助手：小王、小李；另一助手：小王、小张、小陈）。其他人说“记一下”时，是拒绝，还是先记成 pending 等白名单成员确认？
2. **自动记（P4）最终开不开**：建议先影子模式跑一周再定。
3. **个人记忆（P6）**：你之前说先关；开的话建议只在本人私聊里用。
4. **保留期限**：daily 30 天、status 3 天、deadline 截止后 7 天，可以吗？
5. **夜间整理要调模型**（每群每天 1 次，用配置里的模型）：同意吗？不同意就只做规则整理（过期、去重），不重写档案。
6. **群档案 GROUP.md**：由使用这个机器人的人自己审定，不能有客户真名。
7. **对客户的隐私说明**：产品化时要不要默认关掉自动记，只留显式“记一下”？

## 10. 内容策略层（隐私固定开，红线按机器人配置）

框架只内置两样**隐私保护**，所有机器人都开：
- 客户名脱敏：`redact.txt`（每个机器人一份），命中的词替换成“某客户”；
- 个人敏感信息打码：手机号、证件号、邮箱、token 这类密钥样字符串，以及电脑路径。

“哪些话题不谈、哪些内容不记”属于**机器人主人的偏好**，框架不预设任何话题，统一通过配置声明，默认为空：

```json
"policy": {
  "redlines": [],
  "redact_file": "redact.txt"
}
```

某个机器人的主人想加规则时，一条规则这样写（**仅作示例**；例如某位客户不希望群机器人讨论薪资和报价）：

```jsonc
"policy": {
  "redlines": [
    {"name": "薪资与报价", "keywords": ["薪资", "工资", "报价单"],
     "action": "refuse",            // refuse = 入口拒答；drop = 只在出口删段落
     "apply_to": ["input", "output", "memory", "progress"],
     "reply": "这个话题请直接找负责人沟通。"}
  ]
}
```

- `apply_to` 决定规则在哪几处生效：入口（拒答）、出口（删段落）、记忆（不记）、进度卡片（不显示）。
- `redlines` 为空时，guard 只做隐私脱敏，不过滤任何话题。
- 规则同时写进 system prompt 的“规则”块；没有规则就不写，不浪费小抄。

**项目之间怎么隔离**：靠“每个机器人一份配置 + 每个群一份记忆和知识库”，不靠关键词屏蔽表。每个机器人只读自己目录里的 kb、只往自己群的记忆里写，所以本来就看不到别的项目；不需要再写“不许提 X 项目”的屏蔽词。屏蔽词表既会误伤正常提问，又挡不住换个说法的提问。

**落地情况**：框架不内置任何话题红线。示例配置里是 `"policy": {"redlines": []}`。旧键 `taboo_keywords` 还能认，但新配置不要再用它。想限制话题，就在自己的 `policy.redlines` 里写。

## 11. 术语表（按出现顺序）

| 词 | 白话解释 |

| FTS5 | SQLite 自带的全文检索，不用装新东西 |
| 向量索引 | 把文字变成数字向量、按意思相近来找，比关键词聪明但更重 |
| 技能 skill / SKILL.md | 一份“某类事怎么做”的说明书 |
| 渐进披露 / 懒加载 | 平时只给目录，用到才读全文 |
| frontmatter | 文件开头 `---` 之间的几行属性（名字、用途） |
| 工具 / `<<TOOL>>` | 机器人能执行的动作（读群历史、建文档等）；模型用这一行来“申请”调用 |
| `<<MEM>>` | 模型用来“申请”记一条记忆的隐藏行 |
| MCP | 一种让模型直接调用外部工具的标准接口 |
| ACP / 常驻进程 | 让 cursor-agent 一直开着、反复接活的接口方式，省掉每次启动 |
| 流式 | 一边生成一边显示 |
| 白名单 / 确认码 | 允许做写操作的人和资源清单 / 写之前发起人要回复的 6 位数字 |
| 审计日志 | 谁在什么时候做了什么的记录 |
| staging / apply | 先放进待审区 / 审过后正式生效 |
| 看门狗 / 心跳 | 定时检查机器人还活着没有；机器人定时报“我还活着”。长连接断了时心跳仍会更新。可选的断线私聊见 docs/断线提醒与晨报.md |
| dry-run | 不连飞书、不真发消息的演练模式 |
| 单实例锁 | 保证同一个机器人只有一个进程在跑，防重复回复 |
