# 在一台电脑上把三个机器人逐个升到可靠性集成

这一版是草稿 [PR #46](https://github.com/endtree-FDE/feishu-group-agent/pull/46)，分支 `cursor/reliability-integrate-4d5f`。还没有合并，也不要部署到别人的机器。下面是你自己这台电脑上的操作。

三个机器人是三个文件夹。各有各的配置和 profile。一次只动一个，另外两个保持运行。

验证脚本的说明在 [部署后验证.md](部署后验证.md)。

## 先记下来

对每个文件夹运行：

```text
git rev-parse HEAD
git status --short
```

把现在的提交号抄到记事本。回退时用它。不是 git 仓库就抄一下文件夹是从哪一版复制的。

三个 profile 必须各不相同。两个机器人共用一个 profile，就是同一个飞书应用开了两个接收进程。

## 每一个机器人

做完下面 1 到 6，确认没有 `FAIL`，再动下一个。

### 1. 备份

把整个文件夹复制到旁边，名字带上日期，例如 `D:\bots\甲-备份-20261018`。

不要复制到原文件夹里面。不要在备份里改东西。配置里本来就没有 App Secret，密钥只在 lark-cli 里。

### 2. 停这一个

在**这个**文件夹里，用**现在的**停止脚本：

```text
powershell -File scripts\stop.ps1
```

停完看另外两个的窗口或任务管理器，确认它们还在。不要停另外两个，也不要按进程号去结束一个你认不准的程序。

`stop.ps1` 会删掉这个目录的 `bot.pid` 和 `state\bot.lock`。这是正常的。

### 3. 切到 #46

文件夹如果是这个仓库的 git 克隆：

```text
git fetch origin cursor/reliability-integrate-4d5f
git checkout cursor/reliability-integrate-4d5f
```

`agents` 里你填过的配置、`redact.txt`、`kb`、`memory`、`state`、`logs` 都在忽略名单里，切换分支不会把它们删掉。不要提交这些文件。

如果不是 git 仓库：在旁边把这一支克隆下来，只把程序文件拷进这个机器人的文件夹。不要覆盖：

- `agents\` 里已经填好的配置
- `redact.txt`
- `kb\`
- `memory\`
- `state\`
- `logs\`

`state\state.db` 里可能有还没答完的题，留着。

### 4. 旧锁没有 created=

停成功时锁已经删了，直接到第 5 步。

锁如果还在，旧版通常只有一行进程号，没有 `created=`，也没有 `base=`。本版本认这种锁。

- 进程已经不在：启动时把它当成过期锁，接管，写成三行（进程号、`created=`、`base=`）。不会去结束别的程序。
- 进程还是本目录的 `agentbot.py`：`scripts\start.ps1` 会说 `already running` 然后退出，**代码并没有换上**。先确认第 2 步真的停掉了这个目录的进程，再启动。
- 这个进程号已经是别的程序：不当成自己还活着，也不结束那个程序，可以启动。
- 读不到命令行：为了避免同一个飞书应用开出两个接收进程，启动会拒绝，退出码 3。先看这个进程的命令行是不是本机器人。不要因为拒绝就到任务管理器里随便结束。

不要手改锁文件，也不要删另一个机器人的锁。

### 5. 启动

仍在这个文件夹：

```text
powershell -File scripts\start.ps1 -Config agents\甲.json
```

要看到 `started pid`。如果是 `already running`，第 2 步没停掉，现在跑的还是旧程序。如果是 `REFUSED`，按第 4 步看是谁占着，不要结束另外两个机器人。

### 6. 验证

```text
powershell -File scripts\verify_windows.ps1 -Config D:\bots\甲\agents\甲.json,D:\bots\乙\agents\乙.json,D:\bots\丙\agents\丙.json
```

这个脚本不发消息。没有 `FAIL` 就可以停在这里，再升下一个。

刚启动还没有 `events.jsonl`，或者里面还没有错误码，是 `WARN` 或 `OK`，正常。不要为了看错误码去群里 @ 它。

另外两个的进程还在，各自的 profile 每种事件只有一个 `event consume`。

## 回退这一个

只回退刚升过的那一个。另外两个没动过的不要动。

1. 在**当前这份代码**里运行 `powershell -File scripts\stop.ps1`，确认这个目录的进程已经不在。另外两个还在。
2. 把程序换回去：`git checkout` 第「先记下来」里抄的那个提交。不是 git 仓库，就从第 1 步的备份把程序文件拷回来。同样不要覆盖 `agents` 里的配置、`redact.txt`、`kb`、`memory`、`state`。
3. 再用这份旧程序的 `scripts\start.ps1` 启动。

不要在新进程还活着的时候直接运行旧的 `python agentbot.py`。旧程序把整份锁文件当成一个进程号。新锁有 `created=` 和 `base=` 两行，旧程序会觉得这不是数字，把锁当成过期的删掉，再启动一个。这样同一个飞书应用就会有两个接收进程。

先 `stop.ps1`，锁会被删掉，再换回旧程序、再 `start.ps1`，就没有这个问题。旧的 `start.ps1` 只读锁的第一行。新进程如果还没停，它会说 `already running`，不会开第二个。

三个都要退回来的话，仍是一个一个停、换、启。不要一次停三个。

回退之后如果文件夹里已经没有 `verify_windows.ps1`，用备份或 #46 那份脚本单独跑也可以，它不改任何文件。
