# 主理人与专员

比较复杂的问题可以拆开做：查资料、读文档，最后起草一段答复。主理人按问法拆分，不把拆分交给模型，避免正文里的一句话改掉分工。

这项**默认关着**。没有 `agent.crew`，或 `enabled` 不是 `true` 时，回答方式和以前一样。

短句不拆。比较长的问题、一句里有两个问号，或出现「并且」「同时」「分别」「一方面」「先……再」，才会拆。

## 专员只能读

- 查资料：网页、知识库、历史。
- 读文档：飞书文档、知识库、附件、技能说明。
- 起草：只读技能说明，然后写答复。

写入、删除、改日程、往表格里加一行，都不在专员的名单里。模型即使吐出这些调用，也不会执行。真的要写入，仍走原来的白名单和确认码，不能绕过。

都在当前这个接收进程里做，不另开进程，也不新订阅事件。

## 预算

不写这些键时用较宽的默认，适合额度比较多的账号。写 0 或负数时回到默认。写得过大时停在上限，避免停不下来。

| 键 | 不写时 | 上限 |
|---|---|---|
| `total_rounds` | 16 | 100 |
| `step_rounds` | 6 | 30 |
| `total_tokens` | 400000 | 2000000 |
| `step_tokens` | 120000 | 800000 |
| `total_sec` | 900 | 3600 |
| `step_sec` | 240 | 1200 |

模型没有报 token 时，按字数粗算，避免额度形同虚设。到了总预算就用已经读到的材料收束，不再继续拆。

## 怎么开

主人在私聊里发「设置」，找到「主理人」。打开时会把工具一起打开，否则专员读不了资料。关掉主理人不会把工具关掉。
