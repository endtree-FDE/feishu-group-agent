# 技能

技能写的是「这类事怎么做」。知识库是资料，记忆是这个群定过的事，工具是动飞书的手。技能只给步骤，自己不改飞书，也不运行脚本。

默认关着。配置里把 `skills.enabled` 改成 `true` 才生效。还要开着 `features.tools`，否则模型发出的读取不会执行。

自动改进也默认关着。打开之后不会自己改文件。主人私聊发「改进技能」，分数更高并确认，才换成下一版。见 [技能自动改进.md](技能自动改进.md)。

`skills.only` 不写、写成 `[]` 或 `false` 时，文件夹里合法的技能全部进入目录。写成名字列表后，只启用点到的那几个；其余技能不会出现在目录里，`skill_read` 也读不到。旧配置没有这一项，行为与全部启用相同。

## 目录

```text
skills/
  progress-table/SKILL.md
  meeting-minutes/SKILL.md
  topic-ideation/SKILL.md
  short-video-script/SKILL.md
  storyboard/SKILL.md
  aigc-prompt-pack/SKILL.md
  creative-brief/SKILL.md
  post-mortem/SKILL.md
```

每个技能一个文件夹。文件夹名就是技能名字。程序只读里面的 `SKILL.md`，别的文件（如果有）不会自动执行。

## 一份 SKILL.md 怎么写

开头是 YAML 头，后面是步骤。遵循 [agentskills.io](https://agentskills.io/specification)：`name` 和 `description` 必填。

```markdown
---
name: progress-table
description: 查团队进度表。用户问进度、负责人、截止或状态时使用。只读取多维表格，不改表。
triggers: [进度表, 进度, 负责人, 截止, 谁负责]
---

# 查进度表

1. 用 base_read 读取团队多维表格。
2. 只根据返回的记录回答。没有的项写「表里没有」。
3. 先说一句结论，再列出要跟进的项，最多 5 行。
```

规则：

- `name`：1 到 64 个字符，只许小写字母、数字和短横线。不能以短横线开头或结尾，不能有连续短横线，必须和文件夹名相同。
- `description`：1 到 1024 字。写清做什么、什么时候用。这行会进目录。
- `triggers`：可以不写。写的话是一组关键词，用来预判这题要不要直接放进正文。见下面「触发词预放」。
- 正文写步骤。不要写客户真名、密钥、证件号、手机号和电脑路径。

名字用英文短横线，给人看的标题写在正文第一行。例如文件夹叫 `meeting-minutes`，标题写「整理会议纪要」。

## 模型怎么用到它

每次拼提示词，只放一份目录：每个技能一行「名字：描述」。整段不超过 `skills.index_budget_chars`（默认 800 字），超了就截断并注明。

目录放在工具说明之后、群档案之前。启动时扫一遍，同一次运行里这段文字不变，所以改了名字或描述要重启。正文是每次读取时再从文件读的。

模型需要步骤时，只输出一行：

```text
<<TOOL>>{"tool":"skill_read","name":"progress-table"}
```

程序只接受目录里的名字，读出正文（不带 YAML 头），再做脱敏，然后让模型按步骤作答。`../` 这类路径不会去读目录外面的文件。

按步骤如果还要查飞书（例如 `base_read`），可以再输出一行工具调用，然后必须根据结果作答。写操作照旧要确认码。不能连续再读别的技能。

## 触发词预放

`triggers` 写在 YAML 头里，两种写法都可以：

```yaml
triggers: [进度表, 进度, 负责人, 截止]
```

```yaml
triggers:
  - 进度表
  - 进度
```

问题里出现这些词时，程序把那份正文（去掉 YAML 头，并且先脱敏）直接放进这一题的提示词，模型就不用再输出 `skill_read`。没命中的技能仍只在目录里，要用还是走 `skill_read`。

规则：

- 只在 `skills.enabled` 为 `true` 并且 `skills.preload` 为 `true` 时生效。`preload` 不写就是 `true`。`enabled` 为 `false` 时，就算写了触发词也不放。
- 一题最多预放 1 个。命中多个时，把命中的关键词长度加起来，取得分最高的那个。得分相同，用目录里靠前的（按文件夹名排序）。
- 正文不超过 `skills.preload_budget_chars`（默认 3000 字）。超了就截断，并注明已经按字数预算截断。
- 这段放在会变的部分，紧挨在「提问：」前面（有历史或工具结果时，放在它们后面）。技能目录和群档案仍在前面，不因为这一题换了技能而改字。常驻会话冻住的也只是群档案，预放的正文下一题可以换成另一份。

## 自带的技能

| 文件夹 | 做什么 | 不做什么 |
|---|---|---|
| `progress-table` | 用已有的多维表格读取，查进度、负责人、截止、状态 | 不改表、不加记录 |
| `meeting-minutes` | 把讨论整理成结论、待办、负责人、截止 | 不新建文档，不写入 |
| `topic-ideation` | 出选题，并按受众匹配、可执行、辨识度、传播结构、风险打分 | 不编播放量和奖项，不写命理 |
| `short-video-script` | 写短视频口播稿：钩子、按秒分段的正文、画面提示、标题 | 不展开成分镜表，不收集电话 |
| `storyboard` | 出分镜表：镜号、时长、画面、声音/音乐、AIGC 提示词备注 | 不在表里写成长提示词 |
| `aigc-prompt-pack` | 写文生图或文生视频的正向和负向提示词，字段不绑定某一家工具 | 不写某家专有参数，不用在世真人的面孔 |
| `creative-brief` | 把任务收成九节项目策划书 | 没有的信息写「未提及」，不编参考作品 |
| `post-mortem` | 按目标和证据做创作复盘，写出下次保留和下次改的各一条 | 不点名批评，不估算播放量 |

这些都是通用步骤，里面没有真实的人、客户或编号。绘画、民乐配画面、湖山长卷、短视频和投稿只是题材例子。用之前换成你自己的说法即可，也可以删掉不用。

创作技能默认也不启用。`agents/example.json` 里 `skills.enabled` 仍是 `false`，`skills.only` 仍是 `[]`。`only` 为空表示：一旦把 `enabled` 改成 `true`，文件夹里合法的技能会全部进入目录，包括上面这八个。只要创作流程、不要进度表和会议纪要时，在你自己的配置里点名（这段不要写回仓库里的 `example.json`）：

```json
"skills": {
  "enabled": true,
  "only": [
    "topic-ideation",
    "short-video-script",
    "storyboard",
    "aigc-prompt-pack",
    "creative-brief",
    "post-mortem"
  ]
}
```

还要开着 `features.tools`。新建文档、追加和加表格记录仍用已有的 `docs_create`、`docs_append`、`base_create`，并且仍要写入白名单里的人回复确认码。技能只组织文字和提议写入，自己不落盘。用户没明确说保存时，不要提议写入。

一题最多预放一个技能。两个技能的触发词都出现时，命中关键词更长的那个优先；长度相同就用文件夹名靠前的。要分镜又要提示词时，分成两条消息。

## 各技能的短对话

下面每段都是编的。机器人先在回复里给成品。只有用户明确要求保存时，才提议写入。

选题（`topic-ideation`）

用户：给「青绿山水，一分钟短视频」出 6 个选题并打分。

小助手：文首写明默认受众。先说建议先做哪一条，再给打分表。最高分那条写明最大的风险。不调用写入工具。

用户：把这张表存成飞书文档。

小助手：表仍在回复里，并提议 `docs_create`。发起人回复确认码之后，文档才会新建。

口播稿（`short-video-script`）

用户：按建议先做的那条，写 45 秒口播。

小助手：文首写明时长和「未指定平台」。钩子一句，正文按秒分段，每段一句画面提示，三个标题。不编播放量。

用户：改成抖音，30 秒。

小助手：压到 30 到 45 秒。前 3 秒仍是钩子。各段秒数相加等于总时长。

分镜清单（`storyboard`）

用户：把这段口播列成分镜清单。

小助手：一张表，列是镜号、时长、画面、声音/音乐、AIGC提示词备注。时长相加等于口播。没指定曲子就写「未指定曲目」。

用户：写入多维表格，字段还没定。

小助手：不猜字段名。说明改用文档一次写入整张表，并提议 `docs_create`。用户说出字段名之后，再按每轮一条用 `base_create` 提议。

提示词包（`aigc-prompt-pack`）

用户：给第 2 镜写提示词，风格是青绿设色，不要绑某一家工具。

小助手：用户没指定静帧还是视频时，各写一条。正向提示词中文一段、英文一段。负向提示词单独一节。工具对照写「通用，不绑定工具」。

用户：比例改成横屏 16:9。

小助手：正文里的主体不变。参数备注和工具对照改成横屏 16:9，并说明换工具时只改对照。

项目策划书（`creative-brief`）

用户：做一份湖山长卷的项目策划书，用来投稿，截止没定。

小助手：九节都有。截止写「未提及」。不编参考作品的名字。文首说明能不能开工。

用户：存成文档。

小助手：提议 `docs_create`，等确认码。没确认前不说已经写好。

复盘（`post-mortem`）

用户：复盘一下这条短视频：成片 40 秒，分镜返工了两次，因为总时长一开始没定。

小助手：先说有没有达到目标，以及下次最该改什么。证据只用用户这句话。播放量写「未提及」。下次改写成「先定总时长再拆分镜」。不点名批评。

用户：记到已有飞书文档的末尾。

小助手：提议 `docs_append`。文档不在追加白名单里就说明做不到，不绕过确认码。

## 加一个新技能

1. 建文件夹 `skills/<名字>/`，名字按上面的规则。
2. 写 `SKILL.md`：头两行是 name 和 description，下面是步骤。
3. 在仓库根目录运行 `python agentbot.py agents/<配置>.json --check`。技能那一行要有数量；若有 `FAIL skill`，按它写的原因改。
4. 看一遍正文，确认没有客户真名和密钥。
5. 把 `skills.enabled` 改成 `true`，重启。先在不重要的群里试一句，再留着。

配置每一项的意思见 [agents/CONFIG.md](../agents/CONFIG.md) 的「技能」一节。
