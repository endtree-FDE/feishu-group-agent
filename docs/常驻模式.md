# 常驻模式

默认每问一题，就新开一个 `cursor-agent -p`。光启动就要 13–24 秒。常驻模式把这个进程留着，同一话题接着用，省掉反复启动。

默认关着。不改配置，行为和以前一样。

只在 `model_provider` 为 `cursor`（没写这一项时就是 cursor）时有用。换成自己的模型账号见 [模型接口.md](模型接口.md)，那一路没有常驻进程。

## 怎么打开

在这个机器人的 JSON 里，把 `agent.mode` 改成 `acp`：

```json
"agent": {
  "mode": "acp",
  "model": "grok-4.7-high-fast",
  "acp_max_sessions": 8,
  "acp_idle_sec": 1800,
  "acp_allow_web": true,
  "acp_web_max_per_turn": 15
}
```

- `acp_max_sessions`：同时留几个话题。默认 8。多出来就丢掉最久没人问的。
- `acp_idle_sec`：一个话题多久没人问就丢掉。默认 1800 秒。下一问重新开会话。
- `acp_allow_web`：默认 true。允许上网搜索，以及打开 http/https 公网网页。每次只选「允许这一次」，不会选「以后都允许」。本机、内网、共享地址（如 100.64.0.0/10）、IPv6 本地地址不放行。八进制、十六进制、十进制整数和 `127.1` 这种省略写法都按 IP 解释，落在内网就拒绝。解析失败，或短时间内两次解析结果不一致，也拒绝。跳转每一跳都再查一遍，落到内网就拒绝。网址里带账号密码、超过 1024 字，或带有客户名、手机号、邮箱、密钥样子的参数，拒绝。搜索词里夹带这些内容也拒绝。改成 false 则上网也拒绝。假 IP 代理（Clash 的 fake-ip）把公网域名解析到 `198.18.0.0/15` 时，默认仍放行这次「用域名打开网页」；网址里直接写 `198.18.x` 不放行。要改这个段，用 `tools.web.allow_fake_ip_ranges`，见 [agents/CONFIG.md](../agents/CONFIG.md)。`10/8`、`172.16/12`、`192.168/16`、`127/8`、`169.254/16`、`::1` 不会因为写进这个列表而放行。
- `acp_web_max_per_turn`：一轮问答最多放行几次上网。默认 15。超过就拒绝。

改完要停掉正在跑的进程，再启动。只改文件、不重启，旧进程还是旧模式。

可执行文件怎么找，和原来一样：非 Windows 用 `cursor-agent`；Windows 用 `%LOCALAPPDATA%\cursor-agent\versions` 里最新且完整的那一份（旁边要有 `node.exe` 和 `index.js`）。

实际启动参数是：

```text
<原来的 cursor-agent> --model <模型> --mode ask --trust --workspace <知识库目录> acp
```

`--model`、`--mode`、`--trust`、`--workspace` 是全局参数，写在子命令 `acp` 前面。常驻固定用 `--mode ask`（只读）。写飞书仍然只走 `<<TOOL>>`、白名单和 6 位确认码。模型如果要通过常驻进程改文件或执行命令，权限请求拒绝。问新闻这类实时信息时，可以上网搜索并打开公网网页：只放行这一次，一轮里最多 `acp_web_max_per_turn` 次（默认 15），内网地址不放行。联网搜索和打开网页是模型自带的能力；飞书读写才走工具。群记忆改过之后，这个群已经开着的话题会换上新档案，不用把会话关掉重来。

## 怎么确认生效

先做自检，不启动收消息：

```text
python agentbot.py agents\<名字>.json --check
```

`mode` 为 `acp` 时，这一步会真的启动一次进程并做 initialize 握手。

- 成功：有一行 `OK   acp protocolVersion=1`
- 失败：有一行 `FAIL acp`，后面是原因（进程退出、握手超时、协议版本不对等）

然后正常启动，看 `logs/bot.log`：

1. 第一题出现一次 `acp spawn`，接着 `acp ready`，再是 `acp session new`。
2. 同一话题再问，应是 `acp session reuse`，不应再出现新的 `acp spawn`。
3. 另一个话题应是另一个 `acp session new`。

群档案在 `acp session new` 时冻成快照。这个会话还在时，就算有人改了档案，下一问仍用开始时的那份（日志是 `acp snapshot kept`）。发「新话题」、空闲超时、或被挤掉之后，下一问才带上新档案。

## 怎么关回去

把 `agent.mode` 改回 `oneshot`，停掉进程再启动。

旧配置里的 `ask` 和 `plan` 不用改，它们仍是每题一个进程。`plan` 会继续传给 `--mode plan`。

关掉之后，日志里不应再出现 `acp ready`。`--check` 也不再做 ACP 握手。

## 这一题失败时

下面几种情况，**这一题**自动改走原来的 `-p`，并在后台重新拉起常驻进程。下一题再试常驻。

- 进程自己退出
- 超过 `stall_sec` 秒完全没有新输出
- 这一题总时长超过 `max_runtime_sec`
- 协议出错（握手失败、返回错误、空答案）

日志里会有 `acp fallback:`，后面是原因。半截常驻输出不会当成答案发出去。并发上限仍是原来的 `max_concurrency`。

## 在 Windows 上验收

需要这台电脑已经装好 Cursor CLI，并且执行过 `cursor-agent login`（或文档里的 `agent login`）。额度算这台电脑的登录账号。

1. 复制一份不重要的配置，只把 `agent.mode` 改成 `acp`。先不要换到正式群。
2. 运行上面的 `--check`。确认有 `OK   acp protocolVersion=1`。`lark-cli` 那一行失败的话，是飞书命令不在，和常驻无关。
3. 用演练或一个测试群问两句同一话题的话。第一句日志是 `acp session new`，第二句是 `acp session reuse`，中间没有第二次 `acp spawn`。
4. 再问一个新话题，应再出现一次 `acp session new`，进程仍是原来那个。
5. 把 `mode` 改回 `oneshot`，重启后再问一句。日志走原来的一次性进程，没有 `acp ready`。

## 协议依据

2026-10-18 对照过这些页面，不是凭记忆写的：

- https://cursor.com/docs/cli/acp ：启动是 `agent acp`；stdio 上每行一个 JSON-RPC 2.0。顺序是 `initialize`（`protocolVersion` 为 1）、`authenticate`（`methodId` 为 `cursor_login`）、`session/new`、`session/prompt`。流式内容走 `session/update`。要改东西时对方发 `session/request_permission`，决策是 allow-once、allow-always、reject-once。只读模式叫 `ask`。
- https://cursor.com/docs/cli/reference/parameters ：`acp` 是隐藏子命令。`--model`、`--mode`（`plan` 或 `ask`）、`--trust`、`--workspace` 是全局参数。
- https://agentclientprotocol.com/protocol/initialization
- https://agentclientprotocol.com/protocol/session-setup
- https://agentclientprotocol.com/protocol/prompt-turn ：`session/prompt` 的正文是 `[{type:text, text}]`。`session/update` 里用 `agent_thought_chunk`、`agent_message_chunk`、`tool_call`、`tool_call_update`。
- https://agentclientprotocol.com/protocol/tool-calls ：权限选项的 kind 有 `allow_once`、`allow_always`、`reject_once`。上网搜索（kind 为 `search`，并且 toolCallId 以 `web_search` 开头或标题以 `Web search` 开头）以及打开网页（kind 为 `fetch`，并且 toolCallId 以 `web_fetch` 开头或标题以 `Fetch http` 开头）在地址是 http/https 公网时，选 `allow_once`。内网、本机，以及改文件、执行命令，仍选 `reject_once`。没有拒绝项时回 `outcome: cancelled`。绝不选 `allow_always`。
- https://agentclientprotocol.com/protocol/session-modes ：`session/set_mode`，参数是 `sessionId` 和 `modeId`。
- https://agentclientprotocol.com/protocol/schema 和 https://agentclientprotocol.com/protocol/session-config-options ：`session/new` 可以带 `configOptions`。模型项要有可选值（扁平列表，或分组里的 `value`）。只有当前值与配置不一致、并且配置的模型能对上某个可选值时，才发 `session/set_config_option`。请求里的 `configId` 用返回里的 `configId`（没有则用 `id`），`value` 用那个可选值，不把配置里的模型名硬填进去。已经一致、没有可选值、或对不上，就跳过。钉住模型主要靠启动参数 `--model`。调用失败只记 debug，不让这一题失败。2026.10.16 版真 cursor-agent 在 Windows 上每次新建会话都会对无条件的 `set_config_option` 回 `Invalid params`，答题本身是正常的。
