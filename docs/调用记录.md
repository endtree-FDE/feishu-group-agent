# 调用记录

每轮真正交给模型的回答，在本机 `logs/calls.jsonl` 里追加一条调用链。默认开着。旧的 `agents/*.json` 不写这一项也会记。只存在运行机器人的那台电脑上，不发送到飞书以外的服务，也不另起收消息进程。

`logs/events.jsonl` 和 `logs/journal.jsonl` 仍不记问题原文。调用链要能回答「刚才用了什么」，所以会留下脱敏后的短句。

## 一条里面有什么

- 收到的消息（先脱敏，再截短）
- 用了哪个技能、哪个工具
- 每一步的耗时，以及模型这一步报上来的输入、输出 token（没报就是 0）
- 这一步的结果和最后回复（同样先脱敏、截短）

群号、消息编号、open_id 不写入。文件里只有它们的短哈希，用来在本机对上「这条」。

存进去之前会做这些替换：

- 客户名换成「某客户」（名字来自本机的 `redact.txt`）
- 手机号、邮箱、密钥样子的字符串打码，不保留原文
- 本地路径和飞书编号打码
- 工具标记改成看不出的样子，避免以后把日志当成新指令

演练（`--dry-run`、测试替身）和补答会标成演练或补答。用量周报不计这两类。

## 保留多久

`observability.calls.retain_days` 不写是 30 天。写入时丢掉更早的行。小于 1、大于十年或写错，仍按 30 天。要停止记录，把 `calls` 写成 `false`，或 `"calls": {"enabled": false}`。这不会关掉 `journal`。

```json
"observability": {
  "journal": true,
  "calls": {"enabled": true, "retain_days": 30}
}
```

## 主人怎么看

主人的范围和私聊「设置」相同：用量周报或断线提醒的接收人，以及配置里的写入管理员。

在和机器人的私聊里发：

- `最近调用`：最近几条，每条有时间、用过的技能和工具、耗时、token、脱敏后的收到和结果
- `这条怎么答的`：如果回复的是当时那条提问，就解释那一条；对不上就解释最近一条

别人发这两句，只会被告知要找主人，不会附上记录。在群里发，只会说请主人私聊，群里不贴明细。

## 和用量周报

周报打开之后，正文末尾多一段合计：这一周多少条、没答成多少条、token、用过的工具和技能。没有调用记录时，周报和以前一样，不多这一段。明细仍只在本机，周报里不放问题原文。见 [用量周报.md](用量周报.md)。

## 不会做的事

- 不把日志送到外部服务
- 不新订阅飞书事件，也不多开一个 `lark-cli` 收消息进程
- 不因为记了一条调用链就改记忆或改技能
