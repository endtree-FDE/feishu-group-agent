# 在飞书里开关功能

这份说明给不改配置文件的人。主人在和机器人的**私聊**里发「设置」，只收到一张卡片。卡片按你关心的三件事分组：「会主动找你」「回答时会用」「会慢慢变聪明」。每一项一行：一块带颜色的图标、白话名字、一句「开了会怎样」，右边是勾选。卡片上不写序号，也不再写一遍「开」或「关」。

不会先发一段「先看这一项」。点勾选后，还是这一张卡片变成确认，不另发一条消息。可以一次勾几项，只确认一次。

群里不能改。同事在群里问「怎么开某某」，机器人只会请他去找主人，不会在群里讲配置。

## 名字对照

卡片上的名字换成一眼能看懂的说法。以前的说法还能用：回复「打开用量周报」仍然是第一项。

| 卡片上的名字 | 以前的说法 | 开了会怎样 | 和别的项的关系 |
|---|---|---|---|
| 每周用量小结 | 用量周报 | 每周私聊你一份用量合计 | 只私聊，不发到群里 |
| 早上发待办 | 早间待办 | 早上往群里发今天的日程 | 会在群里发消息 |
| 断线告诉你 | 断线提醒 | 连不上时私聊你 | 只私聊 |
| 查资料再回答 | 知识检索 | 提问时用群里的资料，并写上来源 | 不主动发消息 |
| 按步骤写稿 | 技能 | 写稿、做纪要会按现成步骤来 | 下面那一项的父项 |
| 自动优化步骤 | 技能改进 | 根据记录提议步骤的下一版 | 缩在「按步骤写稿」下面。父项关着时这一行变灰 |
| 复杂问题拆开 | 主理人 | 复杂问题分给查资料、读文档、起草 | 不主动发消息 |
| 记住约定 | 记忆成长 | 平时看到的约定，点头才记 | 和下一行不是父子。它看的是平时的约定 |
| 做完记一笔 | 复盘写回 | 这一轮做完写一句，点头才记 | 和上一行不是父子。它只记刚结束的这一轮 |

建议先开「断线告诉你」和「每周用量小结」。这两项只私聊你。早上发待办会在群里发消息，确认之前看清楚再开。

## 谁能改

能改的人是下面这几类里的任意一种：

- 用量周报要私聊的那个人
- 断线提醒要私聊的那个人
- 配置里已经标成管理员、可以让机器人往飞书写东西的人

其他人私聊发「设置」，只会被告知去找主人。

## 怎么操作

卡片回调已经连上、并且确认方式不是纯确认码时：

1. 打开和机器人的私聊，发「设置」。也可以发「功能开关」。
2. 卡片标题是蓝色的「设置」，副标题是「确认后才写入」。飞书的标题色是预设的主题色，不是一张另外上传的头图。
3. 标题下面是一块浅底：大号数字是已经打开的项数，例如 `6 / 9`，旁边一行小字「已开 6/9」，一颗绿点写着「在线」，下面九格进度。版本来自仓库里的 `VERSION`，读不到就不写。上次启动看的是本机锁文件的时间，没有锁就不写时间。
4. 想改某一项，点这一行右边的勾选。卡片当场标成待保存，配置还没写。这一行会多出橙色的「待保存」。底部主按钮写成「保存 N 项改动」。可以连续点几项，只保存一次。再点已经勾上的那一项，会把它撤下。没有改动时，主按钮是浅蓝色，写着「保存 0 项改动」，点不了。
5. 点保存才会备份、写入、检查，然后重新启动。只有你本人、在这同一个私聊里、在有效时间内确认才算数。确认不能关掉。
6. 点取消，卡片回到清单，什么都不改。
7. 次按钮「全部推荐设置」会勾上还没开的「断线告诉你」和「每周用量小结」。已经开着的不动。同样要点「保存」才生效。
8. 想看长说明，点这一行右侧的小箭头。说明就展开在这一行下面：有什么用、打开后会不会主动发消息、要先准备什么。箭头换成朝下。再点一次就收回。卡片上没有「详情」两个字，也没有问号。
9. 「自动优化步骤」缩进在「按步骤写稿」下面。父项关着时，这一行变灰，说明写成「先打开按步骤写稿」。这时点它的勾选，只会提示先打开父项，不会记成待保存，也不会写入。在卡片上把「按步骤写稿」收成关时，如果「自动优化步骤」还开着，会一起放进待保存。回复「第 8 项」或「打开技能改进」仍走原来的文字确认，确认后会把按步骤写稿一起打开。
10. 「记住约定」和「做完记一笔」是两件不同的事，没有收成一项，也不是父子。关掉其中一项，另一项不变。
11. 早上发待办如果在待保存里要打开，卡片上会多一句「早上发待办会发到群里。」
12. 「配置名字」和「确认方式」收在底部一行「高级」里，默认不展开。

确认之后它会自己重新启动，好了再私聊你一声。这中间可能暂时不回消息。

确认方式可以换，不能关掉。在这个私聊里回复「确认方式」就能看现在用的是点按钮还是确认码，并换成另一种。见 [确认方式.md](确认方式.md)。

飞书 7.20 及以上才能画出这张卡片。更早的客户端只能看到标题，并提示升级。

## 卡片没连上时

下面几种情况不发交互卡片，改发一条短文字：卡片回调还没开通、确认方式选的是纯确认码、或者卡片没能发出去。

文字仍带原来的序号，一行一项，例如：

```text
已开 0/9 · v0.9.0 · 在线

会主动找你
1 每周用量小结  关  开了会每周私聊你一份用量合计
4 早上发待办  关  开了会在早上往群里发今天的日程
5 断线告诉你  关  开了连不上时会私聊你

回复序号即可，多个用空格，如 1 5。回复 0 是推荐设置（断线提醒和用量周报）。
```

回复 `1` 仍是每周用量小结。回复 `1 5` 一次改两项，仍要确认一次。回复 `0` 是推荐设置。也可以回复「第 4 项」「打开用量周报」或「打开知识检索」。点了按钮没反应，也用这个办法。

回复数字时，确认是另外一条消息：点按钮，或回复「确认」加数字。不想改就点「取消」，或回复「取消」加同一串数字。

回复「详细」才看文件名和开关在文件里的名字。平时不用看。

## 两套样子

程序发出去的是白底这一套。彩色分组是同一张卡片的另一种 JSON，放在演示目录里，方便对照，当前不会发到飞书上。

两套都只用飞书卡片 JSON 2.0 里真有的东西：蓝色标题主题、标准图标、分栏、细分割线、勾选、折叠面板、按钮。标题的 `template` 只能选预设颜色，不能写成自定义渐变。头图要用已经上传的 `img_key`，仓库里没有这一把钥匙，所以两套都不放横幅，避免画一张飞书画不出来的图。

## 功能开关表

| 卡片上的名字 | 有什么用 | 打开之后 | 要先准备什么 | 怎么开 |
|---|---|---|---|---|
| 每周用量小结 | 每周一份用量合计 | 私聊主人，不发到群里，也不写出别人问过的原话 | 不用准备资料。还没指定主人时暂时不会发出去 | 私聊发「设置」 |
| 查资料再回答 | 回答时引用这个群的资料 | 不主动发消息，有人问才查 | 先把资料放进知识库文件夹，文件夹名字一般是 kb | 私聊发「设置」 |
| 记住约定 | 提议记住平时定过的事 | 默认私聊审批人。不点头不会记 | 不用先写稿。打开时会把长期记忆一起打开 | 私聊发「设置」 |
| 早上发待办 | 早上说今天的日程和未完成任务 | **会发到群里**，每个群每天最多一条 | 日历或任务表要先接上。没指定群就不会发 | 私聊发「设置」 |
| 断线告诉你 | 连不上时告诉主人 | 私聊主人，不发到群里 | 不用准备资料。还没指定主人时只会记在本机 | 私聊发「设置」 |
| 按步骤写稿 | 写稿、做纪要按现成步骤做 | 不主动发消息 | 技能文件夹里要已经有步骤说明 | 私聊发「设置」 |
| 做完记一笔 | 一轮做完后写一句短复盘 | 点头才记进这个群。默认私聊审批人，不点头不记。私聊对话不写进群记忆 | 不用先写稿。打开时会把长期记忆一起打开。还没指定审批人就不会提议 | 私聊发「设置」 |
| 自动优化步骤 | 根据用过的记录提议步骤下一版 | 先对照固定题目，分数没有更高不换。分数更高还要你确认。确认后才能回滚到上一版 | 技能文件夹里要已有步骤说明。文字确认打开时会把按步骤写稿一起打开 | 私聊发「设置」 |
| 复杂问题拆开 | 复杂问题拆给查资料、读文档、起草 | 短句还是原来的答法。专员只能读，写入仍要你确认 | 不用先准备。打开时会把工具一起打开 | 私聊发「设置」 |

## 第一次用

机器人第一次被主人私聊，或者刚装好、已经写了主人是谁，会主动发一段短介绍：能做什么，以及建议先开哪几项。只发私聊，不发到群里。介绍只发一次。

## 改失败了会怎样

确认之后，机器人会先把现在的配置复制一份备份，再写入，再做一次配置检查。检查没通过，或者重新启动没成功，会自动改回备份，并用大白话告诉你原因和下一步。不会留着一份改坏的配置继续跑。

重新启动和本机的停止、看门狗是同一套：先请当前这个自己退出，确认没有第二个接收进程，再启动一个。已经有一个在跑时，不会再开一个。

## 不能在对话里改的

下面这些只能让懂配置的同事改文件，聊天里说了也不会改：

- 飞书密钥、模型密钥
- 模型接口、换成哪一家模型
- 谁可以私聊机器人，包括「所有人都能私聊」

回复「详细」可以看到文件名和开关在文件里的名字。那里没有密钥。

## 给同事看的补充

程序只改下面这些开关，其它键不动。卡片上不显示这些键，除非展开「高级」或回复「详细」。

| 卡片上的名字 | 文件里的名字 |
|---|---|
| 每周用量小结 | `report.enabled` |
| 查资料再回答 | `knowledge.enabled` |
| 记住约定 | `memory.growth.enabled`（打开时同时把 `memory.enabled` 设为开） |
| 早上发待办 | `digest.enabled` |
| 断线告诉你 | `alerts.enabled` |
| 按步骤写稿 | `skills.enabled` |
| 做完记一笔 | `memory.retrospect.enabled`（打开时同时把 `memory.enabled` 设为开） |
| 自动优化步骤 | `skills.evolve.enabled`（文字确认打开时同时把 `skills.enabled` 设为开） |
| 复杂问题拆开 | `agent.crew.enabled`（打开时同时把 `features.tools` 设为开） |

开关先记在本机 `state/switch_menu.json`，大约 30 分钟。这只是待保存，不改配置。点「保存」才用原来的一次性记号写入。记号默认 10 分钟，只认发起人和原来的私聊。飞书还没准备好时，仍用确认码：位数默认 6，存在本机 `state/switches.db`，绑定发起人和会话，过期时间沿用写入确认那一项（不写是 5 分钟）。用过、取消过的不能再用。

一次确认多项时，只备份一次：先关要关的，再开要开的，检查一次，重启一次。检查或重启失败，整份改回这份备份。日志在 `logs/feature_switch.jsonl`，只有动作和哈希，没有编号、确认码和密钥。

飞书卡片是 JSON 2.0。点勾选或箭头后，程序用更新消息把原来那张卡片换成新的内容。长连接收不到网页回调那种响应体，所以不靠 HTTP 响应来换卡片。对照官方文档时，响应形状是 `card.type = raw`，`data` 就是这张卡片。示例见 [demo/README.md](demo/README.md)。

备份在 `state/config-backups/`。Windows 上由 `scripts/reload.ps1` 调用原来的 `stop.ps1` 再 `start.ps1`。还有本目录的接收进程时，脚本退出码是 3，不会再启动。

## 界面参考

下面每条都写了具体借了哪一点。组件只用飞书卡片 JSON 2.0 里现成的，示意图不另加 JSON 里没有的渐变或插画。

- 飞书卡片模板里质感好的那些：标题用主题色、图标用彩色的 `standard_icon`、内容坐在柔和色块上、标题和说明分成两种字号。这里标题用预设的 `blue`。图标按组用橙、蓝、紫，各自坐在 `rgba` 浅底上。方案 B 再给整组铺一层更淡的同色。没有环境里的 `img_key`，所以不加头图。见 [标题](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/content-components/title) 和 [分栏](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/containers/column-set)。
- Apple 设置：一组一个标题，图标有统一的底，右侧控件一样大，行与行之间是细线，子项缩进。父项关掉时，子项变灰。概览用一个大数字，而不是一排重复的开/关标签。
- Linear：白底，颜色几乎只留在图标和状态上，分割线很细，一屏只有一个主按钮。这是现在发出去的那一套。
- Notion：名字下面只用一句人话说明结果。配置名这种内部信息收进最下面，不和开关抢地方。
- Arc：强调色克制。在线状态是一颗绿点，不做成一排标签。
- Raycast 设置：按「它会做什么」分组，不按内部模块名叫「日常 / 记忆 / 技能」。
- 飞书审批卡片：要处理的事用橙色标出来，主按钮放在最下面。这里待保存是橙色，保存是主按钮。
- 飞书没有开关组件。一行右边用 [checker](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/interactive-components/checker)，勾选框大小一致。不写 `behaviors` 时，勾选只在手机上变，服务器收不到。这里写了回调。图标用 [图标库](https://open.feishu.cn/document/feishu-cards/enumerations-for-icons) 里的 `standard_icon`。分栏用 `flex_mode: none`，窄屏按比例压缩，不把勾选挤到下一行。子项前面是一条 16px 的空栏。说明收起时箭头是 `right_outlined`，展开后是 `down_outlined`。「高级」用 [折叠面板](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/containers/collapsible-panel)。
- 不用表单。表单要点提交才把全部值一次交回来，勾选的当时卡片换不过来。见 [卡片 JSON 2.0 组件](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/component-json-v2-overview) 里对 form 的说明。
- 点完之后换掉原来那张卡片，对照 [卡片回传交互](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/handle-card-callbacks) 里 `card.type = raw` 的响应。本机器人走长连接，实际用更新消息写回同一份 `data`。一块主页里改状态、不另开一条消息，这一点对照 Slack App Home。点了之后改原来那条，对照 Telegram 的 editMessageReplyMarkup。
