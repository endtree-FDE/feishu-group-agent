# 记忆成长

长期记忆默认只在有人说「记一下」，或有人确认模型当场提议的那一条时才会增加。记忆成长是另一条路：机器人隔一段时间看本群最近的对话，提议可以记住的事实，也可以提议改掉或停用已经过时的事实。

这项**默认关着**。配置里没有 `memory.growth`，或 `enabled` 不是 `true` 时，不会为它调用模型，不会发提案，也不会改变「记一下」、`/记忆`、`/忘记`。长期记忆本身也要开着（`memory.enabled` 为 `true`）。两个开关缺一个，成长都不跑。

没有审批人用确认码点头之前，什么都不会写进 `facts.jsonl` 或 `GROUP.md`。

## 借鉴了什么

对照过这些做法，只拿能放进现有文件记忆、又不必加新依赖的部分：

| 来源 | 拿来的做法 | 没有照搬的部分 |
|---|---|---|
| [mem0](https://github.com/mem0ai/mem0) | 对照已有事实，一次整理出新增、更新或作废 | 托管服务、向量库 |
| [Letta / MemGPT](https://docs.letta.com/guides/agents/memory-blocks) | 核心档案有字数上限；模型只提议，程序才落盘 | 让模型直接改核心记忆 |
| [LangMem](https://github.com/langchain-ai/langmem) | 后台整理和对话里的「记一下」分开 | LangGraph |
| [Zep / Graphiti](https://arxiv.org/abs/2501.13956) | 事实带来源和有效期；新事实取代旧事实时留下旧的 | 图数据库 |
| Generative Agents 的反思 | 隔一段时间看最近的对话，而不是每一句都记；用把握表示有多值得记 | 把反思直接写成记忆 |

仍然只用 Python 标准库和本仓库已有的模型接口。不上托管记忆。

## 配置

写在 `memory` 里面。`agents/example.json` 里 `enabled` 仍是 `false`。

```json
"growth": {
  "enabled": false,
  "approver_open_ids": ["REPLACE_USER_OPEN_ID"],
  "deliver": "p2p",
  "time": "03:00",
  "timezone": "Asia/Shanghai",
  "window_min": 30,
  "on_schedule": true,
  "on_idle": true,
  "idle_min": 45,
  "lookback_hours": 36,
  "max_messages": 40,
  "max_proposals": 8,
  "review_days": 90,
  "status_days": 3,
  "deadline_grace_days": 7,
  "offer_gap_days": 7,
  "min_confidence": 0.55,
  "dedupe_ratio": 0.9,
  "confirm_ttl_sec": 86400,
  "forget_ttl_sec": 300
}
```

| 键 | 不写时 | 作用 |
|---|---|---|
| `enabled` | `false` | `true` 才整理。长期记忆关着时，写了 `true` 也不跑 |
| `approver_open_ids` | 空 | 谁可以批准。空着或还是 `REPLACE_` 占位时，不调用模型，也不写入。`--check` 会提示 |
| `deliver` | `p2p` | `p2p` 私聊每位审批人。`group` 发在被整理的那个群里，不发到别的群 |
| `time` | `03:00` | 每天开始整理的本地时间。不是 `HH:MM` 时，定时这一路不跑 |
| `timezone` | `Asia/Shanghai` | 上面的时间用哪个时区。认不出时区时不跑 |
| `window_min` | `30` | 到点之后的多少分钟里都可以跑。每个群每个本地日最多定时整理一次，重启也不会再跑第二次 |
| `on_schedule` | `true` | 要不要走定时。`false` 就只剩下面的闲置整理 |
| `on_idle` | `true` | 一段对话闲下来之后要不要整理 |
| `idle_min` | `45` | 这个群最后一次有人 @ 机器人之后，安静这么多分钟，算这段对话结束 |
| `lookback_hours` | `36` | 定时或闲置时，向前看多少小时的群消息 |
| `max_messages` | `40` | 一次最多看多少条 |
| `max_proposals` | `8` | 一次最多提议多少条 |
| `review_days` | `90` | 没有单独到期日的事实，这么多天没有复核就提议作废 |
| `status_days` | `3` | 近况类事实批准后多少天到期。到期后不再注入，并提议作废 |
| `deadline_grace_days` | `7` | 截止日过去后再留几天，然后不再注入 |
| `offer_gap_days` | `7` | 同一条作废提案，这么多天内不重复发 |
| `min_confidence` | `0.55` | 模型给出的把握低于这个数就丢掉。0 到 1 |
| `dedupe_ratio` | `0.9` | 和已有事实有多像才当成同一条，不另记 |
| `confirm_ttl_sec` | `86400` | 提案确认码的有效秒数。过期就不能用 |
| `forget_ttl_sec` | 跟 `write.confirm_ttl_sec`，那项不写则是 `300` | `/忘记` 确认码的有效秒数 |

审批人编号要和飞书 open_id 一样，只含字母、数字、下划线和短横线。不要把密钥写进配置。

群历史工具（`tools.history`）关着时，仍然可以按日期提议作废已有事实，但看不到新的对话，也就不会为新对话调用模型。

## 会提议什么

模型只看这一个群、这一段已经脱敏的对话，以及这个群账本里还在用的事实。它按 JSON 回答，程序再检查一遍。能留下的大致是：

- 已经定了的事
- 截止时间和时间点
- 谁负责什么
- 回答偏好、协作习惯
- 项目进展和近况
- 会反复出现的说法（带主题的那种）

也会提议更新一条旧事实，或作废一条被新说法推翻、已经过期、到了复核日的事实。

下面几种情况不会送给模型，也不会变成提案：

- 对话里没有「决定、负责、截止、改成、偏好、进度」这类词，并且也没有到期要复核的旧事实
- 句子里出现了 `redact.txt` 的客户名、手机号、证件号、邮箱或密钥。整句丢掉，不会改成「某客户」再拿去提议
- 命中了本机器人配置在记忆上的话题红线
- 把握太低、太短、太长、消息编号对不上这个群的这批消息、要更新的编号不在这个群

对话里的话只当资料。里面的工具标记和伪造确认码不会变成指令。

## 审批

提案默认私聊发给每一位审批人。`deliver` 为 `group` 时，发在被整理的那个群，不发到别的群。正文是一份短清单：做什么、一句话、把握、来源日期和消息编号，以及这一条的确认码。

审批人处理某一条：

```text
确认记忆 123456
改记忆 123456：讨论会改到周四下午
驳回记忆 123456
```

`拒绝记忆 123456` 和驳回一样。

绑定规则：

- 码是 6 位，到 `confirm_ttl_sec` 就失效。用过一次就不能再用。
- 私聊送达时，只有审批人本人在和机器人的私聊里回复才算。拿到码的人在群里回复不算。
- 群里送达时，只有审批人本人在**这个群**里回复才算。拿到码去别的群或私聊回复不算。
- 别人回复不会把码用掉。过期、驳回、确认都不会把内容写进别的群。

改过的正文会再做一次脱敏和红线检查。里面仍有客户名、号码或密钥时，这一条不写入，码还留着。

批准新增或更新之后，账本里会多一条 `how` 为 `growth` 的事实。来源里有日期、本群编号、话题编号（能对上时）和消息编号，另外有 `confidence`（把握）。更新会把同主题的旧条目标成已被取代，旧条文还在账本里，但不再注入。作废会把那一条标成过期，不从磁盘上抹掉原文；`/忘记` 才是真删。

近况类事实在批准时带上到期日（默认 3 天）。截止类如果正文里有日期，到期日是那天再加宽限（默认 7 天）。别的事实不自动从档案里消失，但默认 90 天后会再提议复核。到期日已过的事实，在成长开着时不再注入，也不出现在 `/记忆` 里。成长关着时，这些日期不改变原来的档案。

## 去重和冲突

- 同一主题，正文几乎一样（默认重合度达到 0.9）：不再提议，也不改旧条目。
- 同一主题，说法不同：提议更新。批准后新的生效，旧的标成已被取代。
- 没有主题、但和某一条几乎一样：丢掉，不另记。
- 同一批里重复的，只留把握更高的那条。

这发生在写入之前。没人批准，旧事实保持原样。

## 命令

| 命令 | 谁 | 成长关着时 | 成长开着时 |
|---|---|---|---|
| `/记忆` | 群里能 @ 到机器人的人 | 和以前一样，列出本群有效条目 | 一样，但已过到期日的不再列出。带把握的条目会多写一个数字 |
| `/搜记忆 关键词` | 同上 | 长期记忆开着就可以搜，只搜本群 | 一样，已过期的不参与 |
| `/忘记 编号` | 写入白名单 | 立刻真删 | 不立刻删。本人要在同一处回复「确认忘记 123456」 |
| `/忘记全部` | 写入白名单 | 仍要「确认清空」，和以前一样 | 不变 |

`/记忆 搜 关键词`、`/memory search 关键词` 和 `/搜记忆` 相同。搜不到就说没有。私聊不会去读群账本。

成长打开后的单条删除，确认码只认发起人、同一个群、同一个话题（主聊天的码不能拿到话题里用，反过来也不行）。别人拿着码不能删。这和「确认清空」是同一类绑定，用的词不同，避免和飞书写入的「确认 123456」混在一起。

## 隐私和隔离

- 每个机器人自己的目录，每个群一个子文件夹。整理 A 群时不读 B 群的账本，也不把 B 群的消息放进提示词。
- 批准时写入的 `scope` 和来源里的会话，都是提案上的那个群，不是审批人当时随便打开的另一个会话。
- 客户名、手机号、证件号、邮箱、密钥样子的字符串：出现在对话里就整句不提议；出现在模型给出的事实或审批人改的正文里就整条拒绝。
- 展示和注入前仍会再脱敏一次。
- 审计记操作和编号。驳回和作废不把正文再抄进审计。

## 和原来的「记一下」

「记一下」「记住」「备忘」，以及模型在回答时用 `memory_propose` 发出的那一个确认码，都还在。那是当场、由发起人确认的一条。记忆成长是事后整理，交给配置里的审批人。两条路都不会在没人点头时写入。

关掉 `memory.growth.enabled` 之后，已经批准的事实还在。只是不再提议，`/忘记` 恢复成立刻删除。

一轮做完就写一句短复盘，是另一项开关，默认也关着。它复用这里的审批人和「确认记忆」，不另外调用模型。见 [复盘写回.md](复盘写回.md)。
