# 从 0.5.0 升到 0.6.0

这一版不改配置也能接着跑。程序不读 `VERSION`。不要把 App Secret、群号、open_id 或客户名写进配置或聊天。

发布说明见 [v0.6.0](release-0.6.0.md)。0.5.0 的停机和可选开关见 [升级到 0.5.0](升级到0.5.0.md)。

这一版在 0.5.0 之后多了四项，默认都关着：回答质量回归、用量周报、分群知识库检索、记忆成长。下面的步骤把代码换成标签 `v0.6.0`。这份说明不打标签。标签由发布时另打。

## 换代码

在这个机器人的仓库根目录操作。看门狗大约每 3 分钟看一次心跳。进程停了而代码还是旧的，它会把 v0.5.0 再拉起来。进程还在时先换文件，跑着的仍是旧程序，锁和新文件也会对不上。所以 `scripts\stop.ps1` 和 `git reset --keep v0.6.0` 必须在同一步里连续执行，不能拆成「先停、过一会儿再换」或「先换、回头再停」。

1. 进程可以先留着。先把标签取到本机：

```text
git fetch origin tag v0.6.0
```

2. 同一步。在 Windows PowerShell 里整段一次贴上。先停，停成了立刻 `git reset --keep`。中间不要启动，也不要去做别的事。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\stop.ps1
if (-not $?) { throw "stop.ps1 没停成，先不要换代码" }
git reset --keep v0.6.0
if (-not $?) { throw "代码还没换成 v0.6.0，先不要启动" }
```

`stop.ps1` 仍只看本目录和 profile，不会结束旁边另一个机器人。`git reset --keep` 把已跟踪的程序文件换成这个标签，并留下不冲突的本地修改。它不删除未跟踪和被忽略的文件：你自己的 `agents\*.json`、`state`、`kb`、`memory`、`redact.txt`、`logs` 都还在。不要用 `git reset --hard`，也不要 `git clean`。

`git reset --keep` 如果因为已跟踪文件的本地改动冲突而停下，先不要启动。看门狗可能在这几分钟里把旧进程拉起来。处理完提示后，把第 2 步整段再执行一次，然后再启动。

3. 用原来的启动脚本再启动。把配置名换成你这份：

```text
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start.ps1 -Config agents\<名字>.json
```

旧配置不必补 `report`、`knowledge` 或 `memory.growth`。没写或 `enabled` 不是 `true` 时，不发周报，不建分群索引，也不提议新的长期记忆。「记一下」、`/记忆`、`/忘记` 和 0.5.0 一样。

## 换上之后检查

在仓库根目录。两条都不发消息。`--doctor` 不写心跳，不拿单实例锁，也不启动收消息的进程。

```text
python checks/check_config.py agents\<名字>.json
python agentbot.py agents\<名字>.json --doctor
```

`check_config` 只看类型，缺了的键和不认识的键不失败。示例里的 `REPLACE_` 只是占位。`--doctor` 里有 `FAIL` 就先看那一项，不要在群里发测试消息。这台电脑还没装 lark-cli 时，诊断里会有失败项，这和没发消息是两件事。

想在升级前再看回答边界，用假模型跑回归。它不连接飞书，也不占用正在跑的那个进程的锁：

```text
python evals/run.py --config agents\<名字>.json --provider fake --tag ci --baseline evals/baseline/ci.json --out evals/out
```

## 可选：只打开用量周报

另外三项保持关闭。只在你自己的 json 里改这一处，不要把 `knowledge.enabled` 或 `memory.growth.enabled` 设成 `true`：

```json
"report": {
  "enabled": true
}
```

`weekday`、`time`、`timezone`、`window_min` 可以不写。不写就是周一 `09:00`、`Asia/Shanghai`、窗口 180 分钟。`report.owner_open_ids` 不写时，用已经写在 `alerts.owner_open_ids` 里的主人。不要求 `alerts.enabled` 已经打开。两边都空着就不会发，本机记一行，不把编号写进日志。编号不要写进仓库。

改完 JSON 后，再跑一次上面的 `check_config` 和 `--doctor`，然后停掉再启动。周报私聊仍用原来的 `im:message:send_as_bot`，不新加权限。每个主人每周一份。细节见 [docs/用量周报.md](用量周报.md)。

分群知识库和记忆成长先不要开。要开再看 [docs/知识库.md](知识库.md) 和 [docs/记忆成长.md](记忆成长.md)。记忆成长还要求 `memory.enabled` 已经是 `true`，并且填了审批人。没有确认码之前不写账本。

## 退回 0.5.0

退回目标是标签 `v0.5.0`，提交 `e842684`。

同样必须同一步：先 `stop.ps1`，停成了立刻换回标签。不要拆开。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\stop.ps1
if (-not $?) { throw "stop.ps1 没停成，先不要换代码" }
git reset --keep v0.5.0
if (-not $?) { throw "代码还没换成 v0.5.0，先不要启动" }
```

然后再用这份旧程序的 `scripts\start.ps1` 启动。`git reset --keep` 仍保留你的配置、`state`、`kb`、`memory` 和 `redact.txt`。

0.5.0 不认识 `report`、`knowledge` 和 `memory.growth`，多出来的键会被忽略，不会因此发周报或建索引。它不读 `state\report_state.json`、`state\kb\` 和 `memory\_growth\`，这些文件留着也没有关系。若曾经打开记忆成长，退回之后 `/忘记` 又变成立刻删除。回答质量回归的 `evals/` 目录会一起去掉，正式运行本来也不读它。
