# 从 0.4.1 升到 0.5.0

这一版不改配置也能接着跑。程序不读 `VERSION`。不要把 App Secret、群号、open_id 或客户名写进配置或聊天。

发布说明见 [v0.5.0](release-0.5.0.md)。0.4.1 的停机和确认码见 [升级到 0.4.1](升级到0.4.1.md)。

主线上在 0.4.1 之后、这一版之前，已经有创作技能和渠道适配器。下面的步骤把它们和断线提醒、早晨摘要一起换上。四项默认都关着。

## 停和启

1. 用本目录的 `scripts\stop.ps1` 停掉这个机器人。它仍只看本目录和 profile，不会结束旁边另一个机器人。
2. 换成这一版代码。保留原来的 `agents\*.json`、`state`、`kb` 和 `redact.txt`。
3. 用原来的 `scripts\start.ps1` 再启动。

旧配置不必补 `channel`、`alerts`、`digest` 或 `skills`。没写 `channel` 时仍是飞书。`skills.enabled` 不写或为 `false` 时，新的创作技能不会进提示词。`alerts` 和 `digest` 不写或 `enabled` 不是 `true` 时，不发私聊，也不往群里发定时消息。

不要为了升级把 `channel` 改成 `wecom`。企业微信仍是实验骨架，默认不加载，加载了也不连接。

## 可选：打开断线提醒

只有需要时才加。主人的 open_id 写在你自己的 json 里，不要提交。

```json
"alerts": {
  "enabled": true,
  "owner_open_ids": [],
  "unhealthy_after_sec": 180,
  "repeat_sec": 1800,
  "local_log": true,
  "windows_toast": false
}
```

把 `owner_open_ids` 换成主人的 open_id。应用本来就要有 `im:message:send_as_bot`。主人要在应用可用范围里。如果发不出去并提示不在会话中，让主人先给机器人发一条私聊。不要求打开 `features.p2p`。

`unhealthy_after_sec` 留着 180。看门狗仍在心跳超过 3 分钟时重启。写成更大的数时，进程已经死掉的那次通知可能来不及发。长连接断了但进程还在时，计时在进程内部。

改完 JSON 后重启。看门狗只有在这项为 `true` 时，才会在重启前执行 `python agentbot.py <配置> --alert-check`。这条命令不拿锁，也不启动收消息的进程。

## 可选：打开早晨摘要

`digest.enabled` 设为 `true`，写上 `time`、`timezone` 和 `chat_ids`。群必须已经在服务范围内：顶层 `chat_ids` 非空时，摘要里的群也得在里面；顶层留空时，用已经认下的群。机器人要已经在那个群里。

日历编号是真实的时，开放平台加上 `calendar:calendar.event:read` 并发布应用版本。任务表的 `base_token` 和 `table_id` 都是真实的时，加上 `base:record:read` 并发布。`REPLACE_` 开头或空着的编号不会去读。每个群每个本地日最多一条，不会点名所有人。

## 可选：只用创作技能

`skills.enabled` 设为 `true`，`skills.only` 写成要启用的文件夹名。不写 `only` 或写成 `[]` 时，目录里合法的技能都会可用。保存到飞书仍要写入白名单和确认码。

## 退回 0.4.1

退回目标是标签 `v0.4.1`，提交 `deb498f`。

1. 用本目录的 `scripts\stop.ps1` 停掉这个机器人。
2. 把代码退到 `v0.4.1`（`deb498f`）。保留原来的 `agents\*.json`、`state`、`kb` 和 `redact.txt`。
3. 用原来的 `scripts\start.ps1` 再启动。

0.4.1 不认识 `alerts`、`digest`、`channel` 和后来的技能目录，多出来的键会被忽略，不会因此发消息。它不读 `state\health_alert.json` 和 `state\digest_state.json`，这两个文件留着也没有关系。

退到 `deb498f` 时，渠道适配器和六份创作技能也会一起去掉。那两项是 0.4.1 之后才进主线的。确认码、单实例锁和按群成员私聊仍按 0.4.1 的行为。
