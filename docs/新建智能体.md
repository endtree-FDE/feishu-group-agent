# 从零做一个飞书群机器人

按顺序做。做完一步，确认没问题，再做下一步。某一句看不懂，就把那一句发给帮你的人，不要跳过去。

你需要：一台 Windows 电脑、一个能创建「企业自建应用」的飞书账号、一个你自己的 Cursor 账号。

模板里没有任何人的账号。模型默认用 `grok-4.7-high-fast`，额度算在你自己登录的那个 Cursor 账号上。

## 1. 在飞书开放平台创建应用

1. 用浏览器打开 `https://open.feishu.cn/app` ，用你的飞书账号登录。
2. 创建一个企业自建应用。名字用你想在群里看到的，例如「小助手」。
3. 打开「凭证与基础信息」。抄下 **App ID**。先不要复制 App Secret 到任何聊天或文件里。下一步才用，而且只在你自己的电脑上输入。

## 2. 一次申请权限

把下面这一整行里的「你的应用ID」换成刚才抄的 App ID，粘贴到浏览器地址栏打开。页面会列出要开的权限，按提示申请。

```text
https://open.feishu.cn/page/scope-apply?clientID=你的应用ID&scopes=im:message.group_at_msg:readonly,im:message:send_as_bot,im:message.p2p_msg:readonly,im:message:readonly,im:message.group_msg,im:resource,im:message.reactions:write_only,im:message:update,cardkit:card:write,docx:document:readonly,docx:document:create,docx:document:write_only,search:docs:read,calendar:calendar.event:read,calendar:calendar.event:create,calendar:calendar.event:update,calendar:calendar.event:delete,base:record:read,base:record:create,base:app:create,base:table:read,base:table:create,base:field:read,base:field:create,docs:permission.member:create,im:chat:read,im:chat.members:read
```

能自动通过的，加上就生效。仍然要做第 4 步的发布，否则群里用不了。

这些权限分别是干什么的：

| 你希望它能 | 权限 |
|---|---|
| 群里被 @ 时收到，并回复 | `im:message.group_at_msg:readonly`、`im:message:send_as_bot` |
| 私聊 | `im:message.p2p_msg:readonly` |
| 看本群最近的聊天 | `im:message:readonly`、`im:message.group_msg` |
| 看图片和文件 | `im:message:readonly`、`im:resource` |
| 处理中的表情 | `im:message.reactions:write_only` |
| 更新进度卡片 | `im:message:update`、`cardkit:card:write` |
| 搜文档、读文档 | `search:docs:read`、`docx:document:readonly`（文档还要分享给这个应用） |
| 新建文档、在末尾追加 | `docx:document:create`、`docx:document:write_only` |
| 看日历、建/改/删日程 | `calendar:calendar.event:read`、`calendar:calendar.event:create`、`calendar:calendar.event:update`、`calendar:calendar.event:delete` |
| 读表格、加一条记录 | `base:record:read`、`base:record:create` |
| 你亲手建表、建字段时用 | `base:app:create`、`base:table:read`、`base:table:create`、`base:field:read`、`base:field:create` |
| 你亲手把同事加进专用文件夹时用 | `docs:permission.member:create` |
| 查群列表和成员编号，用来填配置 | `im:chat:read`、`im:chat.members:read` |

不要再加「删除消息」「移出群」「改别人权限」「邀请人进日程」这类权限。日程可以改、可以删，但不会删消息、删文档、删表格记录，也不会拉人。见 `docs/安全红线.md`。

暂时用不到的，可以在申请页删掉。以后缺了，机器人会回复「这项权限未开」，不会崩溃。再到这里补，并重新发布。

## 3. 打开机器人，订阅「有人发消息」

1. 在应用里打开「添加应用能力」，加上「机器人」。
2. 打开「事件与回调」。订阅方式选 **使用长连接接收事件**。不要填网址，家用电脑不需要公网。
3. 添加事件：`im.message.receive_v1`（接收消息）。

长连接要等程序在你电脑上跑起来之后才连得上。先把这一项选好，第 12 步再启动。

## 4. 发布，并设好谁能用

1. 打开「版本管理与发布」，创建一个版本。
2. 可用范围选需要用这个机器人的人，或选全员。没被选中的人，私聊和 @ 可能没有反应。
3. 提交并发布。以后每改一次权限，都要再发一版。

## 5. 在 Windows 上安装三个东西

用管理员打开的 PowerShell 也可以，普通 PowerShell 通常就够。

1. 安装 Python 3.12。安装时勾选 **Add python.exe to PATH**。装完关掉窗口再开一个新的 PowerShell，输入 `python --version`，能看到版本号即可。
2. 安装 Node.js（用来装飞书命令行）。然后：

```text
npm install -g @larksuite/cli
```

输入 `lark-cli --version`，有版本号即可。

3. 安装 Cursor 桌面版。打开一个新的 PowerShell，输入：

```text
cursor-agent login
```

按提示用**你自己的** Cursor 账号登录。以后每次回答都用这个账号的额度。不要把别人的账号写进配置，模板里也没有写死的账号。

再输入 `cursor-agent --version`。如果提示找不到命令，先打开一次 Cursor，再试。正式运行时，程序也会自己去安装目录里找完整的那一版。

## 6. 你本人输入应用密钥

这一步必须由应用的主人在自己的电脑上做。帮你的人可以在旁边看，但不要把密钥发给对方。

在 PowerShell 里运行（把应用 ID 换成你的）：

```text
lark-cli config init --app-id 你的应用ID --app-secret-stdin --brand feishu
```

运行后它停下来等你。把 App Secret 粘贴进去，按回车。粘贴时屏幕上可能不显示，这是正常的。不要把 Secret 写在这行命令里面，否则会留在历史记录里。

然后运行：

```text
lark-cli config show
```

把这里看到的 profile 名字抄下来，填进配置的 `profile`。不要把这一屏发到群里。

## 7. 把机器人拉进群，抄编号

1. 在飞书群里添加这个机器人（按应用名字搜）。
2. 在 PowerShell 列出它加入的群（profile 换成上一步的名字）：

```text
lark-cli im +chat-list --as bot --profile 你的profile --page-all --format json
```

找到群名字，旁边那一项就是群编号，填进 `chat_ids`。可以有多个群，一个一项。想改成「拉进群再认、不用每次改配置」，不要填群号，按 [docs/升级已有智能体.md](升级已有智能体.md) 的「14 附」做。默认仍要白名单成员在群里发「/认群」，它不会自己打招呼。

3. 再看这个群里有谁（群编号换成上一步抄到的）：

```text
lark-cli im +chat-members-list --chat-id 群编号 --as bot --profile 你的profile --page-all --format json
```

- `bots` 里这个机器人的 `member_id`，填进 `bot_open_id`。
- `users` 里允许它写文档、改群记忆的人的 `member_id`，填进 `write.allowed_users` 的左边，右边写这个人的称呼。

同一个人在不同应用下的编号不一样。换了应用就要重新查。有的成员如果还没和这个应用建立关系，名字可能显示成「用户」加一串数字，用群里的人数对上是谁。

如果命令说缺权限，回到第 2 步补上，发布新版本，再试。

## 8. 填写配置

1. 复制 `agents/example.json`，改名为 `agents/你的机器人.json`。不要直接改 example，留着当样子。
2. 打开 `agents/CONFIG.md`，按里面的说明逐项填。凡是 `REPLACE_` 开头的都要换掉。
3. `agent.model` 保持 `grok-4.7-high-fast`，或改成你的 Cursor 账号能用的模型名字。不要写账号。
4. 第一次先保持 `memory.enabled` 为 `false`，`progress.enabled` 为 `false`。等第 14 步的真人验收通过，再一个一个打开。
5. 人设 `system_prompt` 和 `texts.help` 里的「小助手」改成你的机器人名字。不要写客户真名。

## 9. 脱敏名单

把 `redact.example.txt` 复制成 `redact.txt`，和 `agentbot.py` 放在同一层。

一行写一个要隐藏的客户名。可以先只有说明、没有名字。以后确认了客户名再加。不要把写了真名的 `redact.txt` 放进公开仓库。

## 10. 跑测试

在有 `agentbot.py` 的文件夹里打开 PowerShell：

```text
python tests/run_tests.py
```

这一步不连飞书，也不用 Cursor 额度。最后一行应是全部通过。有失败就先不要启动，把最后的 FAIL 发给帮你的人。

## 11. 演练（不往飞书发消息）

演练会调用你电脑上的 cursor-agent，**会用你的额度**，但回复只出现在屏幕上。

在记事本里新建 `演练.jsonl`，内容换成你配置里的同一套编号和名字（下面是样子）：

```text
{"event":{"message_id":"dry_1","chat_id":"REPLACE_CHAT_ID","chat_type":"group","message_type":"text","sender_id":"REPLACE_USER_OPEN_ID","sender_type":"user","content":"@小助手 你好，用一句话介绍你能做什么","mentions":[{"id":"REPLACE_BOT_OPEN_ID","key":"@_user_1","name":"小助手"}]}}
```

然后：

```text
python agentbot.py agents/你的机器人.json --dry-run 演练.jsonl
```

屏幕上出现 `[dry-run] reply` 和一句回答，就说明链路通了。不要用 PowerShell 的管道把中文喂给 python，中文会变成问号。用文件，就像上面这样。

## 12. 启动

```text
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start.ps1 -Config agents\你的机器人.json
```

打开 `logs\bot.log`。看到 `ready` 或 `feishu-websocket: connected` 才算连上。没有这两句，就还没在听消息。

这个脚本启动前会结束同一个 lark-cli profile 里残留的 `event consume` 和 `event _bus`，别的 profile 不动。配置里 `conflict_pidfiles` 指向的旧进程还活着时，它打出 `REFUSED` 并且不启动。

停掉：

```text
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\stop.ps1
```

不要在一个马上会关掉的远程窗口里直接启动。窗口一关，程序会一起被关掉。用下面的计划任务来拉起。

## 13. 计划任务和看门狗

让它在你登录 Windows 之后自动启动，并且每 5 分钟看一眼还活着没有。不需要 Windows 密码：

```text
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\register-tasks.ps1 -Mode logon -Config agents\你的机器人.json -Name 你的机器人
```

`-Name` 用一个短名字，例如 `XiaoJing`。它会注册两个任务：`你的机器人-Start` 和 `你的机器人-Watchdog`。

如果你希望**没登录也开机就跑**，把 `-Mode logon` 换成 `-Mode boot`。这时会弹出窗口，要你本人输入 Windows 密码。密码只交给 Windows 的任务计划，不写进任何文件。

看门狗发现心跳超过 3 分钟，或进程不在了，会自己停掉再启动。它只在 `logs\watchdog.log` 记一行，**不会往群里发消息**。

检查看门狗：在「任务计划程序」里运行一次 `你的机器人-Watchdog`，结果应是成功，`watchdog.log` 里没有新的 restart，python 仍然只有一个。

电脑睡眠会掉线。长期开着的话，把睡眠关掉。

知识库如果要从收件箱或飞书文档更新，再注册每天早上的任务。它只把新内容放进待审区，**不会自动换掉**正在用的知识库：

```text
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\kb-sync-task.ps1 -Config agents\你的机器人.json -Name 你的机器人
```

你看完 `kb_staging` 里的报告，确认可以，再在这个文件夹运行：

```text
python kb_sync.py agents/你的机器人.json --apply 日期
```

日期是文件夹名，例如 `20261017`。旧的知识库会留在 `kb_prev`。

这些 ps1 必须是带 BOM 的 UTF-8。仓库里的脚本已经是。不要用记事本换一种编码另存。

## 14. 上线前检查

- `logs\bot.log` 里有 `ready` 或 `feishu-websocket: connected`。
- 任务管理器里只有一个这个机器人的 python。`lark-cli` 里如果看到 `event _bus`，那是它自己的总线，不是第二个机器人。默认只有一个 `event consume`，事件名是 `im.message.receive_v1`。打开了自动认群时，还会多两个：`im.chat.member.bot.added_v1` 和 `im.chat.member.bot.deleted_v1`。同一种事件出现两个，才是重复启动了。
- 你没有往群里发测试消息。
- 请一位同事私聊它一句（如果你开了私聊）。
- 请一位同事在群里 @ 它一句普通问题。
- 白名单里的人让它在专用表里加一条，内容以「测试记录，可删除」开头。它应给出 6 位数。本人回复「确认 那六位」，表里出现这一条。另一个人回复同一个码，应该被拒绝。
- 如果 `redact.txt` 里写了客户名，让它复述一句带这个名字的话，回复里应变成「某客户」。

都通过之后，如果需要，再把 `memory.enabled` 改成 `true`，重启，按 `docs/记忆与命令.md` 记一条再删掉。然后再把 `progress.enabled` 改成 `true`，重启，确认先看到「处理中」，再看到答案。一次只开一个。

出问题先看 `logs\bot.log`：

| 日志里 | 多半是 |
|---|---|
| 没有 Q 开头的行 | 事件没订上、没发布、可用范围没包括这个人，或旧程序还在抢消息 |
| 有 Q，但 agent 报错 | 模型名字、Cursor 是否登录、cursor-agent 是否装全 |
| tool degraded | 按它说的去开权限，或把文档分享给应用 |
| reply ok=False | 网络或发送权限。公司代理时，程序已避开飞书域名走代理；仍失败就看这一行 |
| 同一句回复了两次 | 旧的计划任务还在启动旧程序。停用那个任务，不要删，见下一篇 |
